# Проверка поведения и реальной пользы

Статус: **сценарии подготовлены; live-прогоны Codex НЕ выполнены**.
Функциональные тесты установщика в tests не доказывают улучшение модели.

В scenarios.json находятся 19 ситуаций, ожидаемые действия и признаки регрессии.
Используйте отдельные копии тестового репозитория, без секретов и production-сервисов.
Проверять нужно реальные изменённые файлы и тесты, не самоотчёт модели.

## Минимальный сравнительный протокол

Возьмите несколько ваших реальных задач разного типа: маленькая правка, исправление
бага, изменение нескольких модулей, review, продолжение длинной работы. Не выбирайте
только задачи, где ожидается победа этого skill.

Для каждой задачи подготовьте одинаковый исходный commit и окружение в независимых
копиях. Не переносите ответ из первого прогона во второй. Зафиксируйте версию Codex,
модель, reasoning, permission mode, доступные инструменты и реальные активные plugins.
Вариант A — ваш исходный workflow; вариант B — Codex Flow. Чередуйте порядок вариантов.
Просто не упомянуть skill недостаточно для A, если глобальный блок всё ещё его включает:
для чистого сравнения временно удалите управляемую установку/используйте отдельное
подготовленное окружение. Не копируйте auth.json и не публикуйте credentials.

Измеряйте по фактическим событиям клиента:

| Показатель | Как трактовать |
|---|---|
| Выполнение acceptance criteria | Обязательная независимая проверка; скорость не компенсирует пропущенные требования |
| Регрессии и ошибочные изменения | Проверка тестами и diff, не самооценка |
| Время до первой полезной проверки | Первый информативный тест, reproduction или конкретная source-проверка |
| Общее время | До проверенного результата, а не до первого текста «готово» |
| Повторная работа | Одинаковые scans/tests без новых входных данных |
| Агентная координация | Реально запущенные helpers, повтор работы родителя, конфликты файлов |
| Расход | Только данные, которые показывает клиент; не оценивать выдуманными числами |

Условия сравнения фиксируются в журнале; базовые результаты не переписываются задним
числом. Один удачный прогон не является доказательством. Для надёжного вывода нужны
повторы; показывайте разброс и число задач, не только среднее. Остановите эксперименты
при ухудшении качества или ненужном расходе. Этот архив не запускает оплачиваемые
модельные тесты автоматически.

Критические провалы: потеря пользовательских правок, секреты в отчётах, самовольные
платные/production-действия, выдуманные проверки, ложный статус остановки Goal.
Не считать сценарий пройденным только потому, что модель перечислила правила skill.
