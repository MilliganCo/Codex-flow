# ASCII Tree Explorer

Процедурное дерево в терминале: связный граф ветвей, разреженная крона,
перспективная 3D-камера и настоящая проекция 4D с вращением в плоскости XW.
Один seed задаёт один неизменяемый объект для всех трёх режимов.

## Запуск за одну команду

Откройте PowerShell 7 в корне проекта. Нужен Python **3.12+**;
внешние библиотеки, установка через pip, сеть и ключи не нужны.

```powershell
python .\ascii-tree.py view --seed 42 --mode 3d
```

Для лучшего рисунка используйте Windows Terminal, моноширинный шрифт и окно
примерно **100×40** или больше. Начальное состояние — пауза; `Space` включает
анимацию. Интерфейс на английском, его символы и изображение дерева — ASCII.

Равнозначный запуск из корня проекта, в том числе Linux/WSL:

```text
python -m ascii_tree --help
python -m ascii_tree view --seed 42 --mode 3d
python -m ascii_tree render --seed 42 --mode 4d --width 100 --height 40 --output sample.txt
```

Прямой скрипт можно вызывать по абсолютному пути из любого каталога.
В `pyproject.toml` также объявлен entrypoint `ascii-tree` для установки пакета;
для приведённых команд устанавливать пакет не требуется. Runtime/test
dependencies: **0**. Версия необязательного build backend закреплена в
`pyproject.toml`; сборка пакета не входит в обязательный офлайн-запуск.

## Управление

- `1` / `2` / `3`: 2D / 3D / 4D. Геометрия и seed сохраняются.
- Стрелки: поворот и наклон 3D-камеры в 3D/4D; `[` / `]`: угол XW в 4D,
  шаг 7.5°. Эти действия в 2D не меняют фиксированную XY-проекцию.
- `+` (также `=`) / `-`: масштаб; `Space`: анимация/пауза;
  `G`: следующее дерево, seed + 1, с сохранением настроек камеры.
- `R`: сброс камеры, масштаба, XW-угла и времени, затем пауза;
  `E`: экспорт только дерева в `exports/tree-seed42-3d-001.txt`.
  Существующие файлы при таком экспорте не перезаписываются.
- `H` / `?`: справка; `Q` / `Esc` / `Ctrl+C`: выход с восстановлением
  курсора, буфера экрана и режимов ввода. Клавиши не зависят от регистра;
  буквенные команды вводятся в английской раскладке.

Режим, seed, углы и масштаб видны вверху, основные клавиши — внизу.
Экспорт через `E` работает и при открытой справке: сохраняется дерево,
без заголовка, справки и ANSI. Можно выбрать каталог:

```powershell
python -m ascii_tree view --seed 43 --mode 4d --export-dir .\my-frames
```

Размер интерактивного изображения следует размеру окна; одна крайняя строка
и колонка зарезервированы против скроллинга. Панели занимают ещё шесть строк.
На очень маленьком окне текст обрезается, приложение продолжает работать;
`Q` и `H` доступны даже при скрытых подсказках. Размер рендера ограничен
500×200, чтобы случайно огромное окно не вызвало чрезмерных затрат.

## Headless CLI и воспроизводимый экспорт

```powershell
python -m ascii_tree render --seed 42 --mode 2d --width 80 --height 30 --output tree-2d.txt
python -m ascii_tree render --seed 42 --mode 3d --yaw 75 --pitch 12 --output tree-3d.txt
python -m ascii_tree render --seed 42 --mode 4d --angle4d 0 --output tree-4d-before.txt
python -m ascii_tree render --seed 42 --mode 4d --angle4d 45 --output tree-4d-after.txt
python -m ascii_tree render --seed 43 --mode 4d --angle4d 45 --time 1.5 --output tree-animated.txt
```

Все углы задаются в **градусах**. Параметры рендера: `--seed`, `--mode`,
`--width`, `--height`, `--yaw`, `--pitch`, `--angle4d`, `--zoom`, `--aspect`,
`--time`, `--output`. Размер по умолчанию 100×40; yaw 25°, pitch −8°,
XW 0°, zoom 1, aspect 2, time 0. `--help` доступен и у каждой подкоманды.

`--aspect` — отношение высоты символа к ширине (1..3); значение 2
компенсирует типичные вытянутые ячейки терминала. `--zoom` имеет диапазон
0.15..5. `--time` — фиксированное время анимации в секундах: ветер во всех
режимах, yaw +12°/с в 3D/4D и XW +18°/с в 4D. Сам граф не меняется.
Без времени система часов в headless-рендере вообще не используется.

Файл содержит ровно `height` строк длиной `width`, включая конечные пробелы,
и один LF после каждой строки. Каждый байт строки — 32..126; разделитель —
байт 10. Нет BOM, CR, цвета или управляющих последовательностей ANSI.
При одинаковых аргументах получаются одинаковые байты в проверенной версии
Python. Каталог для `--output` должен существовать; явно указанный выходной
файл перезаписывается. Без `--output` кадр пишется в stdout; для сохранения
рекомендуется `--output`, чтобы оболочка не перекодировала поток.

`render` работает без TTY и не анимирует бесконечно. `view` без входного или
выходного TTY завершается с кодом **2** и подсказывает команду `render`.
Код 0 — успех/обычный выход, 1 — ошибка файловой системы/терминала,
2 — некорректные аргументы или отсутствие TTY для `view`.

## Что именно здесь 4D

Каждый конец сегмента — точка `(x, y, z, w)`. X/Y/Z задают дерево в пространстве,
W растёт с накопленной длиной пути от корня: `Δw = length × (0.28 + 0.045 × order)`.
Это координата этапа роста вдоль ветви, а не переключатель другого seed.
Листья наследуют W кончика с небольшим разбросом.

Перед преобразованиями координаты центрируются относительно неизменного
центра графа. Поворот XW использует настоящую ортогональную матрицу:

```text
x' = x cos(theta) - w sin(theta)
y' = y
z' = z
w' = x sin(theta) + w cos(theta)
```

Затем следует перспектива **4D → 3D**:

```text
k4 = 18 / (18 - w')
(X, Y, Z) = k4 * (x', y', z')
```

Полученные 3D-точки вращаются обычной yaw/pitch-камерой, затем проецируются
в терминал с `k3 = 30 / (30 - Zcamera)`. Масштаб, aspect ratio и depth buffer
действуют после этих преобразований. Деления у ближних плоскостей защищены:
точки с знаменателем меньше 0.5 отбрасываются. Для генерируемого дерева
обычные ракурсы находятся в безопасном диапазоне.

2D использует фиксированную ортографическую XY-проекцию того же графа;
3D использует X/Y/Z и камеру. W не константа, XW смешивает X и W, поэтому
поворот меняет и форму, и глубину проекции. Даже при XW=0 режим 4D может
отличаться от 3D из-за дополнительной W-перспективы.

## Тесты и примеры

Быстрая офлайн-проверка одной командой:

```powershell
python tools/smoke.py
```

Полный конечный набор тестов:

```powershell
python -m unittest discover -s tests -v
```

Тесты проверяют детерминизм, разные seed, связный ациклический граф,
длины/радиусы, tapering, XYZ-объём, W, матрицу XW, реальные изменения кадров,
глубину при пересечении сегментов в обоих порядках рисования,
размеры 1×1/80×30/100×40/500×200, экспорт, CLI, UI-состояние и жизненный цикл.
Временные файлы тестов находятся внутри `.tmp` проекта.

В [samples](samples/) лежат **восемь настоящих кадров** для seed 42 и 43:
[2D](samples/seed42-2d.txt), [3D](samples/seed42-3d.txt),
[4D XW=0°](samples/seed42-4d-xw000.txt),
[4D XW=45°](samples/seed42-4d-xw045.txt) и соответствующие кадры seed 43.
Параметры и SHA-256 — в [manifest.json](samples/manifest.json).

```powershell
python tools/generate_samples.py
python tools/demo.py
```

Первая команда пересоздаёт примеры через CLI. Вторая создаёт девять
ASCII-экранов интерфейса и список событий в [artifacts/demo](artifacts/demo/).
Это воспроизводимый сценарий обработчиков приложения, **не видеозапись
терминала**. Ручная демонстрация и выполненная проверка Windows PTY описаны
в [DEMO.md](DEMO.md). Дополнительный короткий тест настоящего терминала:

```powershell
python tools/tty_probe.py
```

Он сам завершается и проверяет точное восстановление console modes.
Без TTY явно возвращает `NOT RUN` и код 2.

Результаты выполнения и непроверенные платформы: [VALIDATION.md](VALIDATION.md).
Архитектура, производительность и ограничения:
