# Implementation notes

## Структура и решения

`ascii_tree/model.py` создаёт immutable dataclass-граф: Point4, Segment,
Leaf, Tree. Единственный источник случайности — локальный `random.Random(seed)`.
Сначала растёт искривлённый лидер из 13 сегментов, затем девять спирально
расположенных скелетных ветвей с изгибающимися рекурсивными ответвлениями.
Угол размещения близок к золотому, длины и направления варьируются;
терминальные побеги несут маленькие разреженные листовые группы.
Глубина ограничена порядком 4, число сегментов защищено лимитом 3500.
У seed 42 получаются 581 сегмент и 1224 листа. Толщина монотонно убывает
вдоль сегментов; дочерняя ветвь не толще родительского конца.

`projection.py` реализует центрирование, непрерывный слабый ветер,
ортогональное XW-вращение, W-перспективу и yaw/pitch-камеру. Угол и время
редуцируются до периода перед тригонометрией, включая очень большие
конечные CLI-значения. Нефинитные входы и небезопасные знаменатели отсекаются.
Ни движение камеры, ни переключение режимов не генерируют новый граф.

`render.py` растрирует сегменты как приблизительные конические капсулы
с эллиптическим сечением в координатах ячеек. Taper интерполируется;
поперечная координата и глубина определяют оттенок коры. Тонкие ветви
используют направленные `/`, `\\`, `|`, `_`; листва — `.`, `,`, `'`, `*`, `o`.
Покрытие дополняется центральной линией, чтобы субсимвольные веточки
не пропадали между центрами ячеек. Z-buffer выбирает ближайший фрагмент,
перспективная глубина интерполируется через обратные расстояния.
Поверхность толстой ветви приближена выпуклым сечением, листья — точками.
Это CPU-растр символов, без меша, текстур и библиотек графики.

`app.py` отделяет клавиши, время и состояние от терминала. `terminal.py`
работает с ANSI alternate screen и cursor-home; опрашивает клавиши каждые
20 мс, анимация ограничена примерно 12 кадрами/с. На паузе перерисовка
происходит по клавише/resize. В Windows используется `msvcrt` и WinAPI;
для WSL/Linux — `termios`, `select` и буфер фрагментированных Escape-последовательностей.
Windows Ctrl+C читается как клавиша, чтобы не зависеть от унаследованного
обработчика PowerShell; внешний KeyboardInterrupt также перехватывается.
`finally` восстанавливает режимы даже при ошибке внутри терминального контекста.

`cli.py` — argparse, проверка параметров, headless и TTY-защита. Запуск
модулем и прямым скриптом проверен. Единственная build-зависимость
setuptools==75.8.0 закреплена; для исполнения и тестов build не нужен.

## Производительность

Конечный замер `python tools/benchmark.py`, Python 3.12.10 / Windows,
seed 42: генерация около 7.5 мс. Медианы CPU-рендера 100×40:
2D 15.8 мс, 3D 17.2 мс, 4D 19.8 мс (по восемь кадров).
Для 500×200: около 39.8 / 41.8 / 45.8 мс (по три кадра).
Исходные цифры: [artifacts/benchmark.json](artifacts/benchmark.json).
Передача/отрисовка терминалом в эти цифры не входят. Это измерение текущей
машины, а не гарантия частоты кадров на других системах.

Геометрия мала, хранится в памяти один раз. Буфер O(width×height), работа
сегментов ограничена их экранными прямоугольниками. На этом объёме простота
стандартной библиотеки полезнее зависимости от NumPy/Textual/curses.

## Trade-offs и известные ограничения

- На низком разрешении толщина округляется до одной ячейки, а отдельные
  листья сливаются. Для чтения ветвей рекомендуется 100×40; при 1×1
  гарантируется безопасность, а не различимость дерева.
- Символьный z-buffer и точечные листья не являются точной растеризацией
  треугольного меша. На пересечении почти равных глубин возможны изменения
  одного символа; символы наклонных ветвей имеют ступеньки.
- Масштаб вписывания фиксирован для исходного графа, чтобы дерево не
  «дышало» при повороте. Сильный zoom, наклон и 4D-перспектива могут
  обрезать крону. `-` уменьшает масштаб, `R` возвращает исходное состояние.
  Если конец сегмента за near plane, отбрасывается весь сегмент, без
  геометрического рассечения; штатная геометрия при обычных ракурсах туда не попадает.
- На узких/низких окнах справка и панели обрезаются, горизонтального
  скролла нет. Для полной справки расширьте окно или используйте README.
  View ограничен 500×200; headless явно отклоняет большие размеры.
- Гарантия байтового повторения проверена на Python 3.12.10 в этой среде;
  побитовое равенство на других реализациях math/random не заявляется.
  Linux/WSL-backend написан, но на настоящем Linux TTY здесь не запускался.

## Исправления, обнаруженные проверками

Первый полный прогон выявил два нарушения tapering: абсолютный минимальный
радиус делал тонкий конец толще начала, а верхушечная ветвь была толще
родительской. Минимум убран в пользу положительного относительного taper,
верхушка теперь наследует долю родительского радиуса. Регрессионные проверки
охватывают обе ситуации для нескольких seed.

Реальный Windows PTY выявил игнорирование Ctrl+C унаследованным обработчиком
консоли. Raw-key ввод устранил зависимость; повторная отправка Ctrl+C
закончилась кодом 0. Проверка WinAPI до/после подтвердила восстановление
режимов ввода и вывода.
