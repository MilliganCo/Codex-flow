# Verification report

Tested on Windows 11 build 26200, Python 3.12.10, PowerShell 7 and a real
Windows ConPTY. Interactive capture was 80x24 (79 columns are drawable).
Headless renders and UI layout tests additionally cover 100x40 and 80x30.
All commands below run from the project root without installation or network.

## Final automated checks: PASS

```powershell
python -m unittest discover -s tests -v
python tools/smoke.py
python tools/verify.py
```

26 tests passed, zero failures/errors. The final combined run saved
[unittest.txt](artifacts/unittest.txt), [smoke.txt](artifacts/smoke.txt) and
[verification.json](artifacts/verification.json). The smoke check is finite,
uses separate Python processes and works without a TTY.

The tests cover these acceptance boundaries:

1. Seed 42 reproduces the graph and bytes; seeds 42/43/2718 differ. Five seed
   values also pass graph checks: positive lengths/radii, taper along paths and
   across parent/child transitions, exact shared endpoints, finite coordinates,
   bounded segment count, increasing W, substantial Z and W variation.
2. All modes produce exact dimensions and printable ASCII plus LF, without
   ANSI. Sizes include 80x30, 100x40, 500x250, narrow and 1x1 frames. Branch-only
   2D pixels form one 8-connected silhouette. CLI files are LF-only on Windows.
3. Camera orbit/tilt visibly change the frame. Crossing segments show the near
   segment in either draw order; a 180-degree camera turn reverses which world
   segment occludes the other. Reciprocal fragment-depth interpolation is
   checked numerically; reversing all real-tree segments/leaves preserves output.
4. XW rotation mixes X and W, preserves their squared norm, reverses with the
   negative angle and maps the basis correctly at 90 degrees. Distinct XW angles
   produce distinct 4D frames; eye-plane clipping and extreme offscreen lines
   remain finite. The model object is unchanged by every mode switch.
5. CLI help, separate-process deterministic rendering, clean output files,
   invalid arguments and non-TTY view exit pass. UI tests cover reset, animation,
   help, seed update, export collision avoidance, resize/minimum layout, quit,
   KeyboardInterrupt and I/O exception cleanup. These UI-loop checks use mocks;
   they do not prove host-window behavior.

## Real Windows console checks: PASS

[native-startup.json](artifacts/native-startup.json) records a finite actual
startup/draw/shutdown. [native-controls.json](artifacts/native-controls.json)
records keyboard input through ConPTY: `1`, `2`, right/up arrows, `3`, `]]`, `+`,
`E`, `H`, `H`, Space, Space, `Q`. Distinct 2D/3D/4D screens and the help text were
observed in terminal output. The final state remains the same tree at seed 42,
4D, pitch 14, zoom 1.1, with advanced animation time and XW angle. Frames replace
the viewport using cursor-home/alternate-screen control, rather than scrolling.

The E key saved [tree-42-4d-001.txt](artifacts/probe-exports/tree-42-4d-001.txt),
a 79x21 ASCII viewport. The combined artifact check verifies its dimensions and
character range. [native-escape.json](artifacts/native-escape.json) records `G`,
`R`, Esc: seed 43, a new object and default orientation/scale. Q and Esc restored
the console modes from `[503, 7]` to exactly `[503, 7]`.

An initial Ctrl+C probe **failed** by reaching its watchdog; its evidence is
retained in [native-ctrlc.json](artifacts/native-ctrlc.json). Processed control
input was consumed by this ConPTY path. The Windows adapter was corrected to
read Ctrl+C as a key. The real-key retest **passed**, exited with code 0 before
the watchdog and restored the original console modes:
[native-ctrlc-raw.json](artifacts/native-ctrlc-raw.json). Exception-driven
KeyboardInterrupt cleanup also passes the automated UI-loop test.

After the final rendering/input changes, another complete actual-key run passed:
[native-final.json](artifacts/native-final.json). It exercised mode switches,
right/up arrows, XW, zoom, E, help and Q on the final code. The resulting
[tree-42-4d-002.txt](artifacts/probe-exports/tree-42-4d-002.txt) matches a headless
render using the recorded state **byte for byte**. The original tree object and
original console modes were preserved. This final export comparison is also
recorded in `artifacts/verification.json`.

## Saved demonstrations and performance

[artifacts/frames](artifacts/frames) contains six 100x40 LF-only ASCII frames:
seed 42 in 2D, 3D and 4D at XW=0/35 degrees; seed 43 in 2D and 3D. The two
4D frames differ. [manifest.json](artifacts/frames/manifest.json) records the
exact inputs and SHA-256 hashes. They were generated by the actual render CLI.
`python tools/generate_samples.py` reproduces the examples.

`python tools/benchmark.py` measured 20 frames per mode, seed 42, 100x40.
The final run recorded median times of 11.568 ms (2D), 17.482 ms (3D), and
14.290 ms (4D); maximum across these samples was 23.297 ms. Details are in
[performance.json](artifacts/performance.json). This measures generation of a
frame, excluding terminal transmission; animation targets 10 fps, not a promise
for other machines or the maximum frame dimensions.

## Not run / practical limits

Linux/WSL execution, optional pip installation/entrypoint packaging, and visible
Windows Terminal window resizing/font inspection were **not run**. No screenshot
or video was captured. The actual console lifecycle/key tests above are stronger
than a mock startup, but do not replace full host-window visual QA. Follow
[INTERACTIVE_DEMO.md](INTERACTIVE_DEMO.md) for that reproducible manual scenario.

Resize handling is verified by changing reported sizes inside UI-loop tests,
including a tiny layout; actual window resizing remains a manual check. A very
small interactive viewport displays a resize hint. Zoom/oblique 4D angles can
crop branches. Near-plane crossing segments are discarded conservatively.
ASCII strokes and depth shading approximate tubes; they are not a solid-mesh
renderer. Determinism is verified for the tested Python version and environment,
not guaranteed bit-for-bit across every Python/libm implementation.
