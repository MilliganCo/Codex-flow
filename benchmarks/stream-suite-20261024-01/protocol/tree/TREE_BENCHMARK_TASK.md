# Общая задача для A/B-эксперимента: ASCII Tree Explorer

**Версия задания:** 1.0 (замораживается до начала A/B).  
**Назначение:** передать **строго одинаковый текст** одному Sol 6.1 XHigh и конфигурации Codex-flow Full.  
**Режим работы:** самостоятельная разработка готового проекта. Не запрашивать код и подсказки из других веток эксперимента; не обмениваться промежуточными результатами.

## Задача

Создай законченное, приятное для использования терминальное приложение **ASCII Tree Explorer** — интерактивный просмотрщик одного и того же процедурно генерируемого реалистичного дерева в режимах **2D, 3D и 4D**.

Это должно быть **настоящее работающее приложение с исходным кодом, тестами и инструкцией запуска**, а не текстовая иллюстрация в README. Основная платформа — **Windows 11 + Windows Terminal + PowerShell 7**. Дополнительно приветствуется Linux/WSL. Предпочтительно Python 3.12 (можно Textual/другую небольшую библиотеку), но если разумнее другой стек и он доступен в данном окружении, можешь выбрать его и обосновать. Не требуются GPU, интернет, API-ключи, нейросети, веб-сервисы.

### Главное художественное требование

Дерево должно выглядеть узнаваемо и органично, насколько это позволяют обычные ASCII-символы: ствол, ветвление с естественным распределением, ветки разных порядков, уменьшающаяся толщина, листья или хвоя/крона, асимметрия, разнообразие при разных seed. Это не просто символ `Y` и не статичный заранее набранный шаблон.

**Растер изображения состоит только из печатаемых 7-bit ASCII символов** (`ord(c) <= 127`); дополнительные ANSI escape codes для цвета допустимы, но не обязательны. Никаких Unicode-блоков, emoji и готовых картинок в качестве дерева. Допустимая палитра: пробел, `.`, `:`, `'`, `,`, `+`, `*`, `o`, `O`, `-`, `_`, `/`, `\\`, `|`, `#`, `%`, `@` и другие печатаемые ASCII.

## Обязательные режимы

### 2D

Один объект проецируется на символьную плоскость. Ствол и ветви формируют цельный связный силуэт с заметным tapering. Крона/листва не должны полностью скрывать читаемость ветвления. Поддерживай масштаб и обновление seed. Нужна не готовая картинка, а результат общего процедурного генератора.

### 3D

Работай с вершинами в координатах `x, y, z`. Проецируй дерево на экран под управляемым углом просмотра. Реализуй occlusion (например, z-buffer или обоснованный painter's algorithm), корректный порядок ближних/дальних сегментов и ASCII shading, учитывающий глубину, освещение, толщину или плотность. Вращение камеры должно заметно менять изображение; одного горизонтального сдвига символов недостаточно.

### 4D

Режим 4D должен быть **математически осмысленным**: в модели существуют точки с четырьмя компонентами `(x, y, z, w)`; `w` можно использовать как координату возраста/этапа роста ветви. Добавь по крайней мере один настоящий поворот в гиперплоскости `xw`, `yw` или `zw`, который смешивает `w` с пространственной координатой, и последовательно выполняй проецирование **4D → 3D → 2D**. В интерфейсе объясни, что терминал показывает проекцию 4D-данных. Управление углом 4D-поворота обязательно; режим «показать другое 3D-дерево и подписать его 4D» не удовлетворяет задаче.

Опционально добавь timeline/стадии роста/ветер, но не вместо собственно 4D-трансформации.

## Интерактивность

Реализуй управляемое меню/help, понятные горячие клавиши и видимый текущий режим:

| Клавиша | Действие |
|---|---|
| `1` / `2` / `3` | Режим 2D / 3D / 4D |
| `←` / `→` / `↑` / `↓` | Вращение/наклон камеры, где применимо |
| `[` / `]` | Изменение угла 4D-поворота (в 4D) |
| `+` / `-` | Масштаб |
| `Space` | Старт/пауза анимации |
| `G` | Новое дерево/seed |
| `R` | Сброс ориентации и масштаба |
| `E` | Экспорт текущего кадра в чистый `.txt` (без ANSI) |
| `H` / `?` | Справка |
| `Q` / `Esc` | Корректный выход |

Если библиотека терминала требует альтернативной раскладки, сохрани эти возможности и выведи реальные клавиши в help. Переключение режима не должно пересоздавать случайное дерево, если пользователь не нажал `G`.

Приложение должно обрабатывать resize окна, терминал около 100×40 символов, узкие терминалы (без падения), остановку через Ctrl+C и отсутствие интерактивного TTY (headless CLI). Не допускай грубого спама строк вместо обновления кадров при анимации. Для демонстрации желательно не менее двух разных seed.

## CLI и экспорт

Должны существовать **как минимум** три действия или их эквиваленты:

```text
ascii-tree --help
ascii-tree view --seed 42 --mode 3d
ascii-tree render --seed 42 --mode 4d --width 100 --height 40 --output sample.txt
```

Возможно другое фактическое имя entrypoint, но в README приведи действительные команды. `render` должен работать без интерактивного TTY для CI и автоматического сравнения. Сохрани одинаковую геометрию дерева при одинаковом seed во всех режимах. В экспортированном кадре все символы — ASCII, согласованные ширина/высота, нет лишнего цвета и управляющих последовательностей.

Параметры для headless-режима: seed, width, height, mode, углы 3D, угол 4D, deterministic animation frame/time при необходимости. Одинаковые входные параметры → одинаковые байты результата.

## Математика / процедурная генерация

- Формализуй дерево как граф сегментов с положительной длиной, радиусами/толщинами и связями предок→потомок.
- Ствол расширяется у основания и сужается к верхушке; разветвление рекурсивное или через L-system/другой воспроизводимый алгоритм.
- Для 3D модель действительно должна иметь ненулевое разнообразие Z, не быть плоской.
- Для 4D W — не константа для всех вершин. Покажи и протестируй изменение изображения при повороте в плоскости XW/YW/ZW.
- Добавь защиту от выхода за границы при перспективных делениях и от бесконечной рекурсии.
- Рендер рассчитан на текстовые пиксели с неодинаковым соотношением высоты/ширины символа; учти aspect ratio.
- По возможности используй depth-aware символы и/или shading, не разрушающие очертания.

## Тесты

Напиши автоматические тесты не только для главной функции, но и для:

1. детерминизма `seed=42` при одинаковых аргументах;
2. различных деревьев для нескольких seed;
3. связности сегментов и конечности координат;
4. размера выходного кадра (например, 80×30 и 100×40);
5. вывода исключительно ASCII/без ANSI в `.txt`;
6. 3D поворота, видимости отличий проекции и occlusion;
7. 4D наличия переменной W, невыражденной XW/YW/ZW-матрицы и влияния её изменения на кадр;
8. переключения режимов без изменения объекта;
9. headless-рендера, startup/shutdown, неинтерактивного режима;
10. безопасной работы при минимальном размере терминала.

Также приложи простой воспроизводимый smoke test из одной команды. Если какие-то проверки не получилось автоматизировать, добавь воспроизводимые шаги ручной проверки и не заявляй о полном прохождении.

### Критерий завершения

Задание считается выполненным только если оно действительно запускается, пользователь способен визуально переключаться между 2D/3D/4D, а 4D реализует геометрию и поворот с W. Хороший README или красивый статический 2D-картинка сами по себе не достаточны. Не скрывай частично работающие функции и невозможность запуска.

**Работай самостоятельно в выданном пустом workspace.** Не читай файлы другой ветки A/B и независимого оценщика. Не выходи за пределы предоставленного каталога без разрешения. Не подключай платные API и не используй дополнительную модель, если режим эксперимента это запрещает. Делай реальные тесты перед заявлением о завершении.
