# ASCII Tree Explorer

Живое ASCII-дерево с единой процедурной геометрией в 2D, 3D и 4D. Ствол, ветви трёх порядков и отдельные листья генерируются по seed. Переключение режима меняет проекцию, сохраняя объект. Нужен **Python 3.12+**, внешние библиотеки, сеть и GPU не нужны.

## Запуск за 30 секунд

Откройте PowerShell 7 в каталоге проекта, желательно в Windows Terminal с окном около 100×40 и моноширинным шрифтом:

```powershell
py -3.12 -m ascii_tree --help
py -3.12 -m ascii_tree view --seed 42 --mode 3d
```

Если команда `py` недоступна, используйте `python` версии 3.12 или новее. Установка пакета для этих команд не нужна. В Linux/WSL команды те же с `python3` вместо `py -3.12`; интерактивный режим использует POSIX TTY. Работа на Linux/WSL в этой среде не проверялась.

Опциональный entrypoint `ascii-tree` объявлен в `pyproject.toml`: `python -m pip install --no-build-isolation --no-deps -e .`. Для такой установки уже должны быть доступны setuptools и wheel; она не нужна для работы из исходников. Изолированная сборка использует закреплённый `setuptools==80.9.0`. Все команды ниже работают без установки и без скачиваний.

## Управление

1. `1` — 2D; `2` — 3D; `3` — 4D. Режим, seed, углы и масштаб показаны сверху.
2. Стрелки — вращение/наклон камеры в 3D/4D; `[` и `]` — поворот XW в 4D; `+`/`-` — масштаб (`=` тоже увеличивает).
3. `Space` — старт/пауза: в 3D вращается камера, в 4D камера и XW. В 2D сохраняется неподвижная фронтальная проекция.
4. `G` — следующий seed; `R` — начальные углы, масштаб и пауза; `E` — экспорт видимого дерева в `exports/tree_<seed>_<mode>_<номер>.txt`. Старые экспорты сохраняются.
5. `H`/`?` — справка; `Q`/`Esc` — выход; `Ctrl+C` — прерывание с восстановлением терминала (код 130).

Окно можно менять во время работы. При очень малом размере показывается короткое сообщение; после увеличения дерево возвращается. Справка и интерфейс на английском, чтобы вывод оставался ASCII. В кадре экспорта нет интерфейса, ANSI или цвета. Геометрия меняется только через `G`; `R` сохраняет seed.

## Headless CLI и экспорт

```powershell
py -3.12 -m ascii_tree render --seed 42 --mode 2d --width 100 --height 40 --output tree2d.txt
py -3.12 -m ascii_tree render --seed 42 --mode 3d --yaw 70 --pitch -12 --width 80 --height 30 --output tree3d.txt
py -3.12 -m ascii_tree render --seed 42 --mode 4d --angle4d 35 --width 100 --height 40 --output tree4d.txt
py -3.12 -m ascii_tree render --seed 2026 --mode 3d --time 2 --zoom 1.15 --output other.txt
```

Параметры: `--seed`, `--mode`, `--width`, `--height`, `--yaw`, `--pitch`, `--angle4d`, `--zoom`, `--aspect`, `--time`, `--output`. Углы в градусах. Диапазон размера: **1–500 × 1–240**; zoom: **0.1–8**. `--aspect 0.5` задаёт отношение ширины ячейки к её высоте. Если ваш шрифт другой, измените значение. Камера в 2D игнорируется.

`--time` — детерминированная позиция анимации: 3D добавляет 24°/с к yaw; 4D — 9°/с к yaw и 24°/с к XW. В 2D time не меняет изображение. Текущее системное время и глобальный random не используются. Одинаковые параметры на той же версии Python дают одинаковые байты. Экспорт — ровно H строк по W печатаемых ASCII-символов, после каждой строки LF, включая последнюю. Пробелы справа значимы. Для 100×40 файл содержит 4040 байт.

Без `--output` render пишет кадр в stdout. Для сохранения точных байтов на Windows используйте `--output`, чтобы поведение перенаправления не зависело от версии оболочки. Указанный CLI-файл заменяется, если уже существует; для `E` имена всегда новые. Родительский каталог `--output` должен существовать. Ошибки аргументов/файла дают код 2 и сообщение без traceback. Неинтерактивный `view` быстро завершается с кодом 2 и предлагает `render`.

## Что здесь означает 4D

У каждой вершины четыре компоненты `(x,y,z,w)`. XYZ описывают неплоское дерево; W растёт с длиной пути от корня: `w = -2.3 + 0.46 * path_length`. Это координата этапа роста, не физическое время или отдельное случайное дерево.

Поворот в плоскости XW при угле θ:

```text
x' = x*cos(theta) - w*sin(theta)
w' = x*sin(theta) + w*cos(theta)
y' = y
z' = z
```

Далее перспектива 4D→3D: `(x3,y3,z3) = (x',y',z') * 18/(18-w')`. Затем обычные yaw/pitch и перспектива 3D→2D с расстоянием камеры 25. Видимая картинка — **двумерная проекция 4D-данных**, поэтому она может изгибаться и терять привычный силуэт при больших углах XW. Это ожидаемое действие преобразования. В 3D используется исходная XYZ-геометрия; в 2D — её ортографическая XY-проекция.

Рендер учитывает соотношение сторон ячейки, сужение ветвей, направление штрихов и глубину. На каждую ячейку есть depth buffer; порядок перечисления ветвей не определяет перекрытия. Листья рисуются отдельными редкими символами, чтобы сохранялась читаемость ветвления.

## Проверки и примеры

```powershell
py -3.12 tools/smoke.py
py -3.12 -m unittest discover -v
py -3.12 tools/make_samples.py
py -3.12 tools/benchmark.py
```

Первая команда — конечный smoke test: четыре разных проекции, размер/ASCII и корректное завершение без TTY. Вторая запускает тесты геометрии, математического поворота, occlusion, CLI, состояния, resize и shutdown. Тесты работают из корня проекта, временные файлы создаются только в `.tmp/`.

Параметры и SHA-256 — в [samples/manifest.json](samples/manifest.json). Открывайте TXT с отключённым переносом строк и моноширинным шрифтом.
