# ASCII Tree Explorer

Один процедурный граф дерева, три проекции: 2D, 3D и 4D. Органичная асимметричная крона, сужающиеся ветви четырёх порядков и редкие листья. Основная платформа — Windows 11 + Windows Terminal + PowerShell 7. Python 3.12+, без внешних runtime-зависимостей, сети, GPU и API-ключей.

## Запуск за минуту

Откройте PowerShell 7 в каталоге проекта. Проверьте `python --version` — требуется 3.12 или новее. Ничего скачивать или устанавливать через pip для запуска не нужно:

```powershell
python -m ascii_tree --help
python -m ascii_tree view --seed 42 --mode 3d
python -m ascii_tree render --seed 42 --mode 4d --angle4 45 --width 100 --height 40 --output sample.txt
```

`python -m ascii_tree` — основной проверенный entrypoint, эквивалент `ascii-tree` из условия. При установке пакета entrypoint `ascii-tree` также объявлен в `pyproject.toml`. Для работы из исходников установка не требуется. Опциональная упаковка использует закреплённый setuptools 75.8.0; runtime и тесты используют только стандартную библиотеку.

Рекомендуемое окно: 100×40 или больше, моноширинный шрифт. В узком окне текст обрезается, приложение продолжает принимать клавиши. Изменение размера применяется автоматически. Для предотвращения переноса последнего столбца интерактивный растр занимает ширину окна минус один столбец; пять строк занимает интерфейс. У `render` размеры соответствуют аргументам точно.

## Клавиши

- `1 / 2 / 3` — 2D / 3D / 4D; текущее дерево и seed сохраняются.
- Стрелки — вращение и наклон камеры в 3D/4D; `[ / ]` — XW-поворот в 4D.
- `+ / -` — масштаб (`=` также увеличивает); `R` — исходные углы и масштаб; `Space` — анимация/пауза.
- `G` — дерево с seed+1; `E` — экспорт в `exports/tree-SEED-MODE.txt`; существующий файл с тем же именем заменяется.
- `H / ?` — справка; `Q / Esc` — выход с кодом 0; `Ctrl+C` — безопасный выход с кодом 130.

В 3D анимация вращает камеру, в 4D — плоскость XW. В 2D остаётся неподвижная ортографическая проекция. `R` сохраняет состояние паузы. `E` сохраняет последний показанный растр дерева, без интерфейса и ANSI; при открытой справке сохраняется лежащий под ней растр.

## Headless CLI и воспроизводимость

```powershell
python -m ascii_tree render --seed 43 --mode 2d --width 80 --height 30 --output tree-43.txt
python -m ascii_tree render --seed 42 --mode 3d --yaw 80 --pitch 15 --zoom 1.2 --output rotated.txt
python -m ascii_tree render --seed 42 --mode 4d --angle4 0 --output before.txt
python -m ascii_tree render --seed 42 --mode 4d --angle4 45 --output after.txt
python -m ascii_tree render --seed 42 --mode 4d --time 2 --output animation-at-2s.txt
```

Углы CLI задаются в **градусах**: `--yaw`, `--pitch`, `--angle4`. `--aspect .5` — отношение ширины символа к высоте. `--time` прибавляет `0.32 рад/с` к yaw в 3D или `0.27 рад/с` к XW в 4D; в 2D не влияет. Все остальные входные данные остаются прежними. По умолчанию: seed 42, 3D, 100×40, yaw ≈25.783°, pitch ≈4.584°, XW 0°, zoom 1.0. `render --help` показывает все параметры.

`render` не требует TTY. Без `--output` пишет только ASCII-кадр в stdout. Файлы содержат ровно width символов в каждой из height строк, LF после каждой строки, без цвета и управляющих кодов. Одинаковые аргументы дают одинаковые байты в проверенном Python 3.12. Для сохранения точных байтов используйте `--output`, а не перекодирование средствами shell. `view` без TTY сообщает об этом в stderr и возвращает 2. Неверные размеры/NaN/недопустимые параметры также возвращают 2; ограничения размера: 1–1000 × 1–500, zoom 0.1–8.

## Что показывает 4D

Вершина имеет координаты `(x,y,z,w)`. В модели `w = длина пути от корня / 2 - 4`: это координата этапа роста. На стыках ветвей координаты, включая W, совпадают. Новый seed меняет пространственную геометрию; переключение проекции её не пересоздаёт.

Настоящий XW-поворот:

```text
x' = x*cos(a) - w*sin(a)
w' = x*sin(a) + w*cos(a)
y' = y; z' = z
```

Затем масштаб 4D-перспективы `24 / (24 - w')` переводит XYZ в 3D. После вращения камеры применяется 3D-перспектива с расстоянием 32 и преобразование в символьные координаты с учётом aspect ratio. Обе перспективы защищены near-plane clamp. Терминал показывает **проекцию четырёхмерных данных**; целиком четыре измерения на плоскости не видны. При XW=0 изображение может отличаться от 3D из-за перспективы по W. При большом угле наклон/деформация дерева ожидаемы.

## Примеры и тесты

В [examples](examples/) сохранены кадры 100×40 для seed 42 во всех режимах, 4D при XW=0°/45° и seed 43 в 2D/3D. [manifest.json](examples/manifest.json) содержит все параметры (углы внутри options — радианы) и SHA-256. Пересоздание: `python tools/regenerate_examples.py`.

Один конечный smoke test, без сторонних пакетов:

```powershell
python tools/smoke.py
```

Он запускает 31 unittest-проверку и headless subprocess для всех трёх режимов. Полная проверка Windows с настоящим ConPTY, клавишами, resize и выходом:

```powershell
python tools/smoke.py --terminal
```

Отдельно: `python -m unittest discover -s tests -v` или `python tools/terminal_smoke.py`. Терминальный тест создаёт скрытую псевдоконсоль только для этого приложения, завершается за конечное время и сохраняет JSON и VT-записи в `artifacts`. Это реальная Windows-консоль, не подмена isatty. На Linux/WSL используйте обычный smoke без `--terminal`; этот backend реализован, но в данном окружении не запускался.
