# Implementation notes

## Структура и решения

- `geometry.py`: immutable dataclasses, локальный `random.Random(seed)`, один
  граф для всех режимов. 12 сегментов ствола, золотой угол размещения скелетных
  ветвей, ограниченная глубина трёх порядков, кривизна и фототропизм. Каждый
  сегмент ссылается на существующую начальную вершину и родительский сегмент.
  Корневые отростки начинают новый путь от узла 0. Радиусы положительны.
- `math4d.py`: чистые преобразования XW, W-перспектива, камера XYZ и
  проекция с поправкой на пропорции символа. Сгенерированная геометрия
  находится перед near planes; произвольные точки за ними отбрасываются.
- `render.py`: клиппинг Liang–Barsky, дискретные сужающиеся капсулы,
  Z-buffer на ячейку. Для перспективы глубина интерполируется через `1/z`;
  ближняя поверхность перезаписывает дальнюю, независимо от порядка ветвей.
  Боковое освещение, толщина и глубина выбирают ASCII-символы. Листья —
  разреженные непрозрачные точечные фрагменты того же буфера.
- `app.py`, `terminal.py`: отделённые состояние, композиция и адаптер ввода.
  Windows использует `msvcrt`, Win32 VT и сохранение обоих console modes;
  POSIX — cbreak, `select`, разбор escape-последовательностей. Контекстный
  менеджер восстанавливает режимы, курсор и alternate screen при выходе.
- `cli.py`: argparse, headless bytes без текстовой перекодировки.
  Python 3.12 выбран из доступного окружения. Ноль внешних runtime-зависимостей
  упрощает Windows/offline-запуск; `setuptools==75.8.0` закреплён только для
  необязательной сборки пакета. Исходники запускаются без сборки.

## Производительность

Seed 42: 654 вершины, 653 сегмента, 5250 кандидатных листьев; рендерится
примерно 35% листьев, чтобы сохранить читаемость кроны. Работа ограничена
фиксированными числом узлов и глубиной рекурсии. Клиппинг отсекает далёкие
экранные участки до растеризации; CLI ограничивает размеры и масштаб.

В данном окружении Python 3.12.10 измеренная медиана 100×40: 2D — 8.28 мс,
3D — 8.82 мс, 4D — 13.18 мс. 200×60: 10.42 / 12.51 / 15.52 мс.
20 измерений на режим, без стоимости отправки кадра терминалу; это наблюдения,
не гарантия FPS. Генерация — около 27 мс. `tools/benchmark.py` повторяет замер.
Интерфейс ограничен 10 обновлениями/с; в паузе нет постоянного потока кадров.
Размер терминала проверяется при опросе ввода. Время анимации ограничивает
шаг после задержки до 0.25 с, чтобы не было резкого скачка после подвисания.

## Компромиссы и известные ограничения

Текстовая ячейка хранит одну поверхность: это не субпиксельный ray tracer.
Рельеф капсул и их концы приближённые; очень тонкие ветки имеют минимальную
толщину в одну ячейку, иначе связность силуэта потеряется. Радиусы — визуальная
толщина древесины после преобразования осевой линии, не объёмный 4D solid.
При экстремальном масштабе детали и ветви обрезаются краем кадра; сегмент с
концом за near plane отбрасывается целиком, без пересечения с плоскостью.
Для данного ограниченного генератора near plane не пересекается.

Генератор стилизует лиственное дерево, не моделирует ботаническую механику,
столкновения ветвей или полноценный рост по времени. W хранит непрерывный путь
роста; timeline добавляет вращение или ветер, а не пересоздаёт геометрию.
Повторяемость проверена в Python 3.12.10. Совпадение последних floating-point
битов между иными реализациями Python и будущими версиями не проверено.

На узком экране часть подписи/справки обрезается; все клавиши продолжают
работать. При ширине в одну колонку терминал может переносить ячейку, но
вычисления и приложение не падают. Крона лучше читается от 80×30.
Шрифт с иным отношением сторон требует `--aspect`. Работа зависит от VT
совместимого терминала; старая Windows Console не является целевой платформой.
Физический resize Windows Terminal и POSIX-ветка требуют ручной проверки;
автоматические resize-тесты используют заменяемый адаптер размеров.
