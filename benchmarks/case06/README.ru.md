# Case06: наблюдаемые результаты и границы

[Неизменённые рабочие исходники](solutions/README.ru.md) · [Слепая оценка по критериям](blind-review.json) · [Реальные экспорты](comparison.png)

Прежние восемь потерянных баллов Flow: README — пять, реальный Ctrl+C в Windows —
три. Остальные 22 критерия были равны. Две последовательные пробы плана отняли
125,328 секунды до реализации и не измеряли качество приложения. Старый помощник
был полезен и работал преимущественно параллельно; складывать длительность его
запросов с временем root было бы неверно.

Обновлённый Flow убирает автоматическую калибровку из критического пути, не
применяет старые overlays и поручает помощнику ограниченную проверку, пока root
пишет код. Рабочий запуск, README и smoke появляются раньше. Резерв последних 20%
времени — инструкция, без принудительного таймера этапов. Оба получили полные баллы
за README, Ctrl+C и остальные неэстетические критерии. Разница 98/97 — эстетическая.

Оба прошли исходный headless-оценщик 25/25 и реальный ConPTY 57/57. Собственные
наборы тестов: 52 у A и 38 у B. Дополнительные геометрические пробы сохранены как
**14/15 и 12/13, exit 1**: добавленное условие ошибочно требовало изменения W больше
0,1 для одной точки. [Отдельный числовой аудит](evidence/observed-rotation-audit.json)
подтверждает исходный критерий по уже полученным SDK-значениям и формулам:
delta W = 0,0171744683, смешивающий синус = 0,6018150232, определитель = 1,
ошибка нормы меньше 1e-12. [Обе](evidence/geometry-13.json) [исходные пробы](evidence/geometry-14.json)
сохранены; приложения не исправлялись, повторных прогонов и изменения рубрики нет.

Завершение исходных процессов подтверждено. Windows позже переиспользовала номер
PID B; защита упаковщика сверяет время создания и не посылает сигналы посторонним
процессам и не читает их имена.

Отдельный A/B-эксперимент с явно указанным замороженным runtime b33ad9cdba0b8fde7efe75ef2572eedc0667c472: Sol 6.1 XHigh. Слепая оценка завершила 26 критериев и пять критических условий; принятых артефактов: 2/2. Приёмка артефакта не меняет исходного статуса процесса.

Наблюдаемые интеграции:

| Ветка | Связанные помощники | Mercury success | Локальные пробы |
|---|---:|---:|---:|
| A | n/a | 0 | 0 |

B использует обновлённый Flow: guard с отложенной калибровкой, 0 online-проб, без adoption и без доказанного выигрыша активного Harness²-оптимизатора. Помощник подтверждается связью родитель→потомок в native-метаданных, не запрошенной моделью/effort. Неизвестное число остаётся null; единичные вызовы Mercury не доказывают качество маршрутизации.

Полный aggregate публикуется только при завершённых запросах всех фаз с известным usage. Нижние границы завершённых запросов сохранены отдельно; накопительные бюджетные счётчики не складываются. Деньги/квота неизвестны, если не измерены. RSS/CPU — выборочные root/probe PID, без потомков и удалённой модели.

Frozen-discovery, ошибки тестов и terminal-сценариев сохранены. Если дополнительные CLI-проверки не выполнялись, указан not_run; их результаты не выдумываются. Лимит времени не равен времени завершения. Case05 остаётся отдельной исторической записью: A=97/100, B=89/100, прежний runtime 343d395; эти баллы не заменяют результаты нового runtime. Cases не объединяются, проценты ускорения и причинный вклад не вычисляются.

Сохранены реальные raw-хеши выполнения. Публикация эквивалентна указанному коммиту только после нормализации LF, а не побайтово и не автоматически последнему main. Старые результаты не переименовываются, поздние изменения не включаются задним числом. Изоляция общего native-состояния/профилей остаётся degraded. ZIP только локально; native-тела запросов/приватные инструкции, сырые native/auth-данные, базы/журналы, stderr и личные пути не публикуются; общее замороженное задание доступно в протоколе.
