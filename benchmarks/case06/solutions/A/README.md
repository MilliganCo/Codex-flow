# ASCII Tree Explorer

Интерактивное дерево в терминале: один процедурный объект, три проекции — **2D, 3D и 4D**. Python **3.12+**, без сторонних библиотек, GPU, интернета и API-ключей. Основная платформа — Windows 11, Windows Terminal, PowerShell 7; предусмотрен POSIX-ввод для Linux/WSL.

## Запуск за минуту

Откройте PowerShell **в каталоге этого проекта**:

```powershell
python --version
python -m ascii_tree view --seed 42 --mode 3d
```

Установка зависимостей не нужна. Если `python` не найден, установите Python 3.12+ обычным для вашей системы способом. Рекомендуемый размер окна — **100×40** или больше; используйте моноширинный шрифт. В Windows Terminal работает Consolas/Cascadia Mono. Выход — `Q`, `Esc` или `Ctrl+C`.

Реальный entrypoint, не требующий установки пакета, — `python -m ascii_tree`:

```powershell
python -m ascii_tree --help
python -m ascii_tree view --help
python -m ascii_tree render --help
```

`pyproject.toml` также объявляет команду `ascii-tree` для установок пакета. Для полностью автономного запуска используйте команды с `python -m` выше; сборка пакета не требуется.

## Управление

1. **`1` / `2` / `3`** — 2D / 3D / 4D. В заголовке виден режим и seed. Переключение сохраняет тот же объект; **`G`** создаёт дерево со следующим seed.
2. **Стрелки** — поворот/наклон камеры в 3D и 4D; **`[` / `]`** — угол 4D-поворота с шагом 8°. **`+` / `-`** — масштаб; `=` тоже увеличивает масштаб.
3. **`Space`** — анимация/пауза: лёгкий ветер, в 3D — орбита камеры, в 4D — ещё и вращение с W. В 2D камера фиксирована, анимируется ветер. **`R`** сбрасывает ориентацию, масштаб, время и ставит анимацию на паузу; seed сохраняется.
4. **`E`** — сохранить текущую проекцию дерева в `exports/tree_seed42_3d_001.txt`; последующие экспорты получают новые номера. **`H` / `?`** — справка поверх дерева, с паузой анимации на время чтения.
5. **`Q` / `Esc` / `Ctrl+C`** — выход с восстановлением курсора, режимов консоли и основного экрана. Буквы работают в верхнем и нижнем регистре при английской раскладке.

Приложение использует дополнительный экран и перемещает курсор при обновлении. Последние физические строка и колонка зарезервированы, чтобы избежать прокрутки. В окне 100×40 рабочая область интерфейса — 99×39, а область дерева — 99×34. Экспорт через `E` содержит **только область дерева**, без меню и рамок. При уменьшении окна изображение подстраивается; ниже 28 колонок или 10 строк появляется компактное меню. Команды продолжают работать даже при размере 1×1, но для чтения нужно увеличить окно.

## Headless CLI и экспорт

Команда `render` не читает клавиатуру и работает с перенаправленными потоками, в CI и без TTY:

```powershell
python -m ascii_tree render --seed 42 --mode 2d --width 100 --height 40 --output tree2d.txt
python -m ascii_tree render --seed 42 --mode 3d --yaw 35 --pitch 15 --output tree3d.txt
python -m ascii_tree render --seed 42 --mode 4d --angle4 48 --plane xw --output tree4d.txt
python -m ascii_tree render --seed 7 --mode 3d --width 80 --height 30 --time 1.25 --output seed7.txt
```

Без `--output` или с `--output -` кадр поступает в stdout. **Для файла используйте `--output`**, чтобы кодировка перенаправления конкретной версии PowerShell не влияла на результат. Каталог назначения должен существовать. Явно указанный CLI-файл перезаписывается; интерактивный `E` существующие файлы не перезаписывает.

Каждый файл содержит ровно `height` строк по `width` печатаемых ASCII-символов, включая конечные пробелы, и LF после каждой строки. Нет ANSI, CR, BOM, Unicode и метаданных. Для 100×40 это ровно **4040 байт**. Одинаковые аргументы дают одинаковые байты в одной среде Python; headless-рендер не использует часы системы.

Доступны `--seed`, `--mode`, `--width` (1–500), `--height` (1–200), `--yaw`, `--pitch`, `--angle4` (углы в градусах), `--plane xw|yw|zw`, `--zoom` (0.1–6), `--aspect` (0.25–1), `--time` (секунды детерминированного ветра). Размеры задаются только для `render`; `view` использует размер терминала. `--aspect` — отношение ширины символа к высоте, по умолчанию 0.5. В `render` камера определяется явными углами; `--time` меняет только ветер. В 2D углы камеры и 4D игнорируются.

`view` без интерактивных stdin **и** stdout быстро завершится с кодом 2 и подсказкой использовать `render`; бесконечного вывода кадров в pipe нет. Коды завершения: 0 — успех/обычный выход, 1 — ошибка I/O, 2 — неверные параметры/нет TTY, 130 — Ctrl+C в Python. PowerShell может отображать ненулевой код команды как общий код ошибки оболочки.

## Что именно означает 4D

Генератор сохраняет вершины `(x, y, z, w)`, сегменты с радиусами и индексами предков. `w` — накопленная длина пути роста от корня, умноженная на 0.48; она возрастает вдоль каждой ветви. Это координата стадии роста, а не отдельная случайная форма дерева. Вершины имеют настоящее разнообразие Z и W; во всех режимах используется тот же неизменяемый граф.

Перед преобразованием дерево центрируется по Y и W. Для XW применяется ортогональный поворот:

```text
x' = cos(a) * x - sin(a) * w
w' = sin(a) * x + cos(a) * w
y' = y; z' = z

4D -> 3D: (X,Y,Z) = (x',y',z') * D4 / (D4 - w')
3D -> 2D: yaw + pitch; затем перспективная камера
```

Поэтому изменение `[` / `]` смешивает возраст с пространством, меняет форму и перекрытия проекции. Это **проекция 4D-данных на терминал**, а не вид четырёх измерений напрямую. Даже при угле 0° 4D отличается от 3D из-за перспективы по W. `--plane yw` и `--plane zw` выбирают другие настоящие гиперплоскости. Деления защищены near-plane-проверками.

2D использует ортографическую XY-проекцию этого графа; Z участвует в видимости. 3D использует XYZ, управление камерой и буфер глубины на каждую символьную ячейку. Толщина уменьшается от основания к верхушке и от крупных ветвей к побегам. Символы `# % :` передают поверхность толстых ветвей; `| / \\ -` — направление тонких, `o * ' .` — разреженную листву и глубину. Поправка на пропорции символа предотвращает сжатие дерева по горизонтали.

## Тесты и smoke test

Из корня проекта, без дополнительных установок:

```powershell
python -m tools.smoke
python -m unittest discover -s tests -v
```

Smoke — восемь конечных проверок, включая CLI, смену режимов, экспорт, resize, occlusion и 4D. Полный набор проверяет также граф, tapering, матрицы, минимальные размеры, управление, восстановление терминала при исключениях, ошибки CLI и воспроизводимость сохранённых примеров. Временные файлы тестов остаются в `.tmp/` внутри проекта. Фактические результаты и границы проверки — в [TEST_REPORT.md](TEST_REPORT.md).

- [interactive_demo.txt](examples/interactive_demo.txt) — 11 экранов **сценарного воспроизведения** настоящего цикла приложения с имитированными вводом и часами; это не запись живого терминала.

Пересоздать примеры и сценарий:

```powershell
python -m tools.generate_examples
python -m tools.demo
```

Ручной сценарий на 90 секунд для Windows Terminal:

1. Запустите `python -m ascii_tree view --seed 42 --mode 2d` в окне около 100×40. Убедитесь, что видны ствол и разветвления; нажмите `2`, затем несколько стрелок. Seed остаётся 42, форма проекции меняется.
2. Нажмите `3`, затем `]` шесть раз. Заголовок показывает XW 48°, дерево деформируется. Нажмите `Space`, подождите 3 секунды, снова `Space`: движение останавливается. `H` открывает/закрывает справку.
3. Нажмите `E`; внизу появится путь к чистому `.txt`. Нажмите `G`: seed становится 43 и дерево меняется. `+`, `-`, затем `R` проверяют масштаб и сброс.
4. Уменьшите окно примерно до 20×8, затем верните 100×40. Приложение остаётся живым. Нажмите `Q`: курсор и основной экран восстановлены.
5. Запустите снова и выйдите через `Ctrl+C`; затем отдельно проверьте `Esc`. Для другой гиперплоскости запустите `python -m ascii_tree view --seed 42 --mode 4d --plane yw`.

Архитектура, ограничения и стоимость рендера описаны в [IMPLEMENTATION_NOTES.md](IMPLEMENTATION_NOTES.md).
