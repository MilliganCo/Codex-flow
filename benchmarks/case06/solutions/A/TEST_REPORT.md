# Проверки ASCII Tree Explorer

Дата: 2026-10-23. Среда: Windows, PowerShell 7, Python 3.12.10. Все команды запускались внутри выданного workspace; сеть, внешние сервисы, дополнительные модели и Git-операции не использовались.

## PASS — итоговая автоматическая проверка

```powershell
python -m unittest discover -s tests -v
```

**52 теста прошли за 12.217 с, exit 0. Нет failed/skipped.** Проверен итоговый совместный код, включая исправление Windows Ctrl+C, компактную справку и сохранённые примеры.

1. Генератор: повторяемость seed 42, различия seed 7/42/314, независимость от глобального RNG, один связный корневой граф без циклов, положительные длины/радиусы, tapering, конечные координаты, ненулевые диапазоны Z и W, ограниченная рекурсия для нескольких seed.
2. Проекции: размеры 80×30 и 100×40, минимальные 1×1/2×3 и узкие кадры, только печатаемый ASCII и LF, отсутствие ANSI; настоящее изменение геометрии проекции при yaw/pitch, фиксированная XY-проекция в 2D, aspect ratio и детерминированный ветер.
3. Видимость и 4D: правильное перекрытие пересекающихся трубок при обоих порядках отрисовки, меняющаяся глубина внутри сегмента; ортогональность и обратимость XW/YW/ZW, известный поворот на 90°, near-plane guard, изменение кадров во всех трёх гиперплоскостях, безопасные большие углы и zoom.
4. Приложение: сохранение идентичности объекта при смене режимов и управлении, генерация только по G, camera/zoom/reset/play/help/quit, полный production event loop с подменным терминалом, экспорт, восстановление при KeyboardInterrupt/ошибке вывода, resize от 99×39 до 1×1 и обратно, отсутствие перерисовок при простое, Windows и ANSI-клавиши.
5. CLI и артефакты: реальные подпроцессы help/version/render всех режимов, одинаковые байты повторного рендера, экспорт файла совпадает со stdout, неинтерактивный view завершается с подсказкой, неверные аргументы/путь не дают traceback; SHA-256 и содержимое шести сохранённых кадров совпадают с текущим renderer.

## PASS — живой Windows PTY

В реальном Windows PTY 80×24 под PowerShell запущен `python -m ascii_tree view`. Это была проверка приложения и нативного Win32/msvcrt-ввода, а не только подмена транспорта в тесте.

- Seed 42: переключение 2D → 3D → 4D, стрелки (наблюдались yaw 343° и pitch 14°), XW-поворот до 8°, справка поверх дерева, анимация с меняющимся углом, пауза и reset.
- Экспорт через E: `.tmp/live-exports/tree_seed42_4d_001.txt`, 79×18, **1440 ASCII-байт**. Отдельная проверка сравнила файл побайтно с headless-рендером seed 42 / 4D / yaw 343 / pitch 8 / angle4 8 — совпадение.
- G изменил seed 42 → 43 и видимую форму дерева; seed 7 отдельно запускался в 2D. Q завершил приложение с кодом 0.
- После исправления Ctrl+C проверен повторно на живом PTY: процесс завершился, выданы последовательности восстановления курсора/основного экрана; PowerShell напечатал **`PYTHON_EXIT=130`**.
- Esc отдельно завершил приложение с восстановлением экрана; **`PYTHON_EXIT=0`**. После изменения режима ввода повторно проверены стрелка, переключение 3D/4D, XW и экспорт.

При первой живой проверке Ctrl+C поглощался обработкой Windows console input. Исправлено отключением processed input и переводом полученного `\x03` в `KeyboardInterrupt`; исходные console modes восстанавливаются при выходе. В раннем тесте compact help выявлялся IndexError для пустого фонового кадра — исправлен дополнением строк перед наложением help. В итоговом прогоне оба исправления включены, открытых падений не обнаружено.

## PASS — демонстрационные артефакты

```powershell
python -m tools.generate_examples
python -m tools.demo
```

Сохранено шесть чистых кадров 100×40 по 4040 байт; seed 42: 2D, 3D, 4D XW 0°/48°; seed 7: 2D и 3D. Между 4D-кадрами 0° и 48° различаются **1107 символьных ячеек**. `examples/manifest.json` содержит аргументы и SHA-256. Примеры проверяются полным набором тестов.

`examples/interactive_demo.txt` содержит 11 воспроизводимых экранов production UI с фиксированными часами и сценарием клавиш. Это сценарное воспроизведение с подменным терминалом, не скриншоты и не запись живого PTY. Ручной сценарий проверки приведён в README.

В данном запуске генерации примеров render занял 43.9–103.0 мс/кадр, медиана 67.4 мс; замер шести кадров выполнен под текущей нагрузкой и не является гарантией FPS.

## NOT RUN и ограничения

- Живой Linux/WSL TTY не запускался: среда Windows. POSIX-декодер покрыт тестами, но это не заменяет нативную проверку ОС.
- Resize мышью в отдельном графическом окне Windows Terminal и субъективная оценка шрифтов не выполнялись. Размеры 100×40, узкие и минимальные проверены в renderer/production loop с подменным терминалом; живой PTY предоставил 80×24.
- `pip install`, сборка wheel и установленный console script `ascii-tree` не запускались. Проверен автономный entrypoint `python -m ascii_tree`; runtime dependencies отсутствуют.
- Буфер глубины и трубки имеют символьное разрешение и приближённое освещение; при очень малом размере крона сливается, а ниже 28×10 UI показывает компактное меню. Near-plane clipping отбрасывает инцидентный сегмент целиком. Подробности — в IMPLEMENTATION_NOTES.md.
- Побайтовая повторяемость проверена в текущей среде Python; отдельное сравнение между версиями Python/разными математическими библиотеками ОС не выполнялось. При включённой анимации E экспортирует текущую логическую проекцию, которая может опережать последний экран на долю кадра.
