# Implementation notes

## Основные решения

Python 3.12 и стандартная библиотека дают автономный запуск в Windows без curses, компилятора, установки пакетов и сети. Runtime/test dependencies отсутствуют; необязательная сборка в `pyproject.toml` закрепляет setuptools 75.8.0. Проверенный способ запуска — `python -m ascii_tree` из checkout.

`model.py` строит неизменяемый граф из 3376 сегментов: изогнутый сужающийся лидер, нерегулярные мутовки, четыре порядка ветвления, повороты концов вверх и небольшие разреженные группы листьев. Азимуты используют золотой угол с seeded jitter. Один локальный `random.Random(seed)` исключает влияние глобального RNG. Рекурсия ограничена константным порядком 4, цепочки — четырьмя сегментами. Связность задаётся общими индексами вершин; родитель каждого сегмента предшествует ему в массиве. Размеры ветвей, наклоны, асимметрия и листва меняются с seed; число сегментов намеренно фиксировано.

`geometry.py` содержит явные 4×4 матрицы XW/YW/ZW, 4D-перспективу и 3D-поворот. W — расстояние роста по пути в графе, не высота и не случайная метка режима. Центрирование W делает поворот удобнее: объект вращается относительно середины диапазона возраста. 4D-повороты сохраняют норму и имеют обратную матрицу; это проверяется отдельно от изображения.

`render.py` проецирует точки, учитывает aspect ratio и растеризует сужающиеся трубки. Центры коротких сегментов oversample-ятся для связного следа. Каждый текстовый пиксель имеет глубину: ближние листья могут закрывать дальние ветви, ближние ветви — дальние листья; порядок отправки дальнего/ближнего сегмента не определяет результат. Глубина внутри спроецированного сегмента интерполируется через обратную глубину. При равной глубине дерево приоритетнее листа. Освещённость толстой ветки стилизована фиксированным боковым светом на экранном сечении, дальние тонкие ветви ослабляются до `:`. Листья — отдельные односимвольные частицы. Экспорт не включает UI.

`state.py` хранит камеру отдельно от дерева. Смена режима, анимация, reset и help не заменяют объект. G увеличивает seed на единицу, что позволяет воспроизвести новое дерево через CLI. Детерминированный ветер применяется только при проекции, с нулевым смещением в момент 0; исходные вершины остаются прежними.

`terminal.py` включает VT-вывод через Win32, читает Windows-клавиши через `msvcrt`, использует `termios/select` на POSIX. На Windows Ctrl+C читается как клавиша и превращается в `KeyboardInterrupt`: это оказалось необходимо при реальной проверке через PowerShell/ConPTY. Режимы консоли сохраняются и восстанавливаются в context manager, включая ошибки вывода. На POSIX сохранён ISIG. Дополнительный экран, cursor-home и резерв строки/колонки предотвращают обычную прокрутку при обновлениях.

`app.py` проверяет resize каждые 25 мс ожидания ввода, рисует по изменению состояния, а при анимации ограничивает частоту до 12 кадров/с. Часы и транспорт терминала подменяемы, поэтому один и тот же production loop можно проверять без TTY конечным сценарием. `cli.py` отдельно от UI выполняет render и записывает ASCII-байты с LF, обходя Windows newline translation.

## Trade-offs и известные ограничения

- Дерево — стилизованное широколиственное. Нет выбора породы, физической ботаники, прозрачных листьев и мешей. На малом разрешении многочисленные побеги сливаются; в 1×1 гарантирована безопасность, не читаемость. Ниже 28×10 интерактивный UI показывает компактное меню вместо дерева.
- Буфер глубины хранит одну поверхность на ячейку. Радиусы трубок и боковое освещение приближённые, без точного пересечения луча с цилиндром/нормалей. При идентичной глубине и приоритете действует первая запись; это может влиять на символ в общих узлах, но не раскрывает далёкий сегмент через ближний.
- Near-plane guard безопасно отбрасывает точку и инцидентные сегменты, если она слишком близка к камере; точного отсечения трубки по 4D-гиперплоскости нет. Для генерируемого дерева камеры расположены достаточно далеко; zoom меняет масштаб экрана, а не положение глаза. Screen clipping ограничивает работу на максимальном zoom.
- Анимация зависит от реального elapsed time и скорости терминала. Headless-кадры детерминированы явными углами и `--time`; интерактивные тайминги сами по себе не являются воспроизводимым экспортным форматом. E сохраняет текущую логическую проекцию (при движении она может отличаться на долю кадра от последнего обновления экрана). Сценарный demo использует фиксированные часы.
- Linux/WSL-ввод реализован и его ANSI-декодер тестируется, но живой Linux/WSL TTY в данном Windows-окружении не запускался. Полный визуальный resize мышью в отдельном окне Windows Terminal не выполнялся; изменение размеров проверено production loop с подменным терминалом. Пакетный build/install не запускался: для модульного entrypoint он не нужен.

## Производительность и защита

На этой Windows/Python 3.12.10 среде первичная генерация seed 42 заняла примерно 40 мс. Для шести сохранённых кадров 100×40 замерено 44–103 мс/кадр, медиана 67 мс; это ориентир конкретного запуска под нагрузкой, не обещание FPS. В живом PTY анимация работала; целевой максимум — 12 кадров/с, фактическая скорость ниже при медленном выводе.

Количество сегментов/листьев ограничено конструкцией; сложность рендера — O(V + L + покрытие сегментов), память буфера — O(width × height). Размер кадра ограничен 500×200, zoom — 0.1–6. Неинтерактивный view завершается до входа в event loop. Проверяются конечность углов, времени, масштаба и aspect. Большое конечное время сводится по периоду перед тригонометрией. Все тестовые подпроцессы имеют timeout, сценарные terminal drivers — ограничение числа чтений. Файлы тестов создаются только внутри checkout.
