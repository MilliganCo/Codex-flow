# Implementation notes

## Устройство

- `model.py`: immutable dataclasses, локальный RNG, tapering ствола,
  ветви в локальном пространственном базисе. Глубина ограничена четырьмя
  порядками, дополнительный бюджет — 4000 сегментов. Начало дочернего сегмента
  точно равно концу родителя, включая W.
- `geometry.py`: явная XW-матрица и последовательные 4D/3D перспективы.
  Near-plane проверки защищают деления. Проекции не вызывают генератор.
- `render.py`: tapered capsules, обратная интерполяция глубины, per-cell
  z-buffer для ветвей и листьев. Физическая метрика учитывает aspect ячейки;
  минимальная полутолщина 0.5 строки удерживает связность тонких веток.
- `state.py` отделяет управление от ОС. `terminal.py`: Windows msvcrt/ctypes,
  POSIX select/termios, alternate screen, скрытый курсор, отключённый wrap,
  адресная перерисовка. Context manager восстанавливает modes даже при ошибке.
  Windows raw input доставляет Ctrl+C как клавишу и затем возвращает код 130.
- `cli.py`: argparse, проверка конечности чисел/размеров, ASCII bytes с LF.
  Нет сторонних runtime/test зависимостей; Python 3.12+ выбран для offline-запуска.

## Trade-offs и ограничения

Это художественная модель широколиственного дерева, без ботанической симуляции
и предотвращения пересечений ветвей. W обозначает возраст вдоль пути роста,
не физическую модель пространства-времени. Плоскость 4D-поворота фиксирована XW.

Z-buffer использует глубину оси с небольшой поправкой поверхности; это
приближение цилиндра. Нет сглаживания/прозрачности. Тонкие веточки получают
похожую символьную толщину, tapering заметнее на крупных ветвях и стволе.
`B` / `--bare` помогают читать скелет при плотном наложении листьев.

Большой zoom и экстремальный ракурс обрезают дерево по viewport. Для текущего
генератора eye planes лежат с запасом. Произвольный импорт не поддерживается;
сегмент, пересекающий near plane, целиком пропускается вместо точного clipping.
Для 4D используется фиксированный дополнительный запас кадрирования, чтобы
перспектива по W не обрезала стандартные примеры. Он не меняется с XW-углом.
Кадры 1×1 безопасны, но полный UI/help требуют крупного окна. Viewer использует
фактические размеры терминала; E экспортирует только область дерева без UI.

## Производительность и платформа

Дерево генерируется один раз. В паузе перерисовка происходит только после ввода
или resize. Анимация ограничена 12 FPS. Bounding boxes растеризуются только внутри
viewport. На текущем Windows/Python 3.12.10: генерация seed 42 около 14 ms,
медианы рендера 100×40 около 25 / 23 / 26 ms для 2D / 3D / 4D.
Это CPU-замеры без терминального вывода; подробности в `artifacts/benchmark.json`.

Windows console/ConPTY проверен реально. POSIX adapter реализован, Linux/WSL
в этом окружении не запускался. Resize проверен симуляцией; ручной GUI resize
остаётся шагом DEMO.md. `pip install` не требовался и не проверялся.
