# Настройка workflow: реальные контроли sandbox

[English](README.md)

Проверено на Windows 27 октября 2026 года с установленным Codex CLI
0.164.0-alpha.11.1. **Реальных вызовов моделей — 0; код приложения и проверяющего
на основном компьютере не исполнялся.** Это проверка инфраструктуры.

Все 14 заранее объявленных случаев дали ожидаемый результат:

| Контроль | Результат |
| --- | --- |
| Рабочее приложение; новый тестовый файл | Приняты; 1 и 2 реальных успешных теста |
| Ошибка приложения; изменение исходного теста | Отклонены |
| Пустой набор; все тесты пропущены | Отклонены даже при разрешённых пропусках |
| Смешанный набор; пропуск в setUpClass, allowance 1 | Приняты; по 1 успешному тесту и 1 пропуску |
| Expected failure; unexpected success; ошибка импорта; subtest failure | Отклонены |
| 800 тестов; 801 тест | 800 успешных приняты; превышение отклонено |

Дополнительный полный контроль использует `workflow init`, связанный контракт по
умолчанию, один **фиктивный** генератор, одну реальную проверку sandbox и обычный
отчёт. Все четыре стадии завершены по одному разу; принят сохранённый результат.
Исходное ошибочное приложение осталось неизменным. Списано одно синтетическое
резервирование запроса; это не вызов модели и не измерение расхода подписки.

`proof-result.json` разделяет реальные результаты unittest и служебные проверки.
`preregistration.json` фиксирует ожидания до выполнения; `frozen-runtime/` хранит
точные 24 модуля runtime. `proof-script.py` — точная копия инструмента; файлы
связаны размерами и SHA-256 в `publication.json`. Native-состояние, исходные
receipts и временные пути сохранены локально. Записанные хеши относятся к исходным
receipts; их содержимое не редактировалось для публикации.

Повторение с проверенным существующим Windows sandbox и новым каталогом:

```powershell
python -B tools/check_workflow_setup.py --root C:\work\new-setup-proof --codex C:\tools\codex.exe
```

Инструмент отказывает при существующем выходном каталоге. Фикстуры записываются
как данные; на хосте импортируется только доверенный runtime Flow. Приложение и
проверяющий запускаются исключительно через `codex sandbox`. Во время проверки
хеши runtime должны оставаться неизменными. Установки, включения моделей и правок
глобальных настроек нет. Для точного сравнения используйте commit, соответствующий
`frozen-runtime/`.

Ранний локальный контроль 14 случаев прошёл до усиления приёмки; его исходные
артефакты сохранены. Опубликован итоговый запуск с дополнительным полным контролем
и исправленным runtime. Он не доказывает защиту от враждебного Python-теста,
улучшение качества или скорости моделей, доступ аккаунта либо запуск Terra.
