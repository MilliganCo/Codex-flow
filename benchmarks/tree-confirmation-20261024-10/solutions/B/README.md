# ASCII Tree Explorer

Интерактивное процедурное дерево в **2D, 3D и настоящей 4D-проекции**.
Python **3.12+**, только стандартная библиотека. Интернет, GPU и установка
зависимостей для запуска не нужны. Основная платформа — Windows Terminal /
PowerShell 7; есть адаптер ввода Linux/WSL.

## Запуск

Откройте PowerShell в каталоге проекта:

```powershell
python -m ascii_tree --help
python -m ascii_tree view --seed 42 --mode 3d
```

Если `python` не найден, на Windows используйте `py -3.12` вместо `python`.
При желании можно установить консольное имя `ascii-tree` через
`python -m pip install --no-build-isolation --no-deps .`, если локально уже есть
setuptools. Установка пакета необязательна; проверенный способ — `python -m ascii_tree`.
`pyproject.toml` закрепляет сборочную зависимость, runtime-зависимостей нет.

## Управление

- `1` / `2` / `3`: режим 2D / 3D / 4D; объект и seed сохраняются.
- Стрелки или `WASD`: поворот/наклон камеры в 3D и 4D. `[` / `]`: XW-поворот
  на 8 градусов в 4D. `+` / `-`: масштаб; `=` тоже увеличивает масштаб.
- `Space`: анимация/пауза. В 2D дерево слегка покачивается, в 3D поворачивается,
  в 4D дополнительно меняется XW. `R`: исходная ориентация, масштаб и время.
- `G`: следующий seed. `E`: экспорт видимой области дерева в `exports/`.
  Предыдущие интерактивные экспорты не перезаписываются.
- `H` / `?`: справка. `Q` / `Esc`: выход. `Ctrl+C`: выход с восстановлением
  терминала. Режим, seed, углы, масштаб и статус анимации видны на экране.

UI занимает пять строк и оставляет последнюю колонку свободной от autowrap.
На узком экране используется компактный вид. Resize отслеживается автоматически.
Для нормального просмотра рекомендуется около **100×40**; шрифт — моноширинный.

## Headless CLI и экспорт

```powershell
python -m ascii_tree render --seed 42 --mode 2d --width 80 --height 30 --output tree-2d.txt
python -m ascii_tree render --seed 42 --mode 3d --yaw 70 --pitch 15 --width 100 --height 40 --output tree-3d.txt
python -m ascii_tree render --seed 42 --mode 4d --angle4d 0 --width 100 --height 40 --output before.txt
python -m ascii_tree render --seed 42 --mode 4d --angle4d 45 --width 100 --height 40 --output after.txt
python -m ascii_tree render --seed 137 --mode 3d --time 1.5 --output another-seed.txt
```

Углы `--yaw`, `--pitch`, `--angle4d` задаются в градусах. Есть `--zoom` (0.1..8),
`--aspect` (ширина/высота ячейки, по умолчанию 0.5), `--time` (детерминированное
время анимации в секундах). По умолчанию: seed 42, 100×40, yaw 25°, pitch −7°,
XW 0°, zoom 1, time 0. Полная справка: `python -m ascii_tree render --help`.

`render` не требует TTY. Без `--output` кадр идёт в stdout. `view` при отсутствии
интерактивных stdin **или** stdout выдаёт один чистый кадр и завершается.
Выходные файлы имеют ровно width столбцов, height строк, печатаемый ASCII и LF
после каждой строки, без ANSI и без заголовков. Сохраняйте конечные пробелы при
сравнении. Одинаковые параметры дают одинаковые байты на одной версии Python.

`render --output` атомарно заменяет названный файл; каталог должен существовать.
Интерактивный `E` сохраняет именно область дерева без панелей UI, поэтому её
размер меньше размера окна. Для строго 100×40 используйте headless-команду.
Некорректные параметры и ошибки записи завершаются с кодом 2 и сообщением в stderr.

## Что происходит в 4D

Один неизменяемый граф содержит вершины `(x,y,z,w)`, радиусы и связи родителей.
W нарастает вдоль пути развития ветви. Ни переключение режима, ни поворот не
запускают генератор заново. XYZ имеет ненулевой объём по Z.

2D использует ортографическую XY-проекцию. В 3D применяются повороты yaw/pitch,
перспектива, z-buffer на каждую символьную ячейку и освещение толщины ветвей.
В 4D центрированные/нормализованные координаты сначала вращаются в плоскости XW:

```text
x' = x cos(a) - w sin(a)
w' = x sin(a) + w cos(a)
(x3,y3,z3) = (x',y,z) * 4 / (4 - w')
```

Далее используется та же 3D-камера и проекция в терминал. Это **проекция 4D-данных**:
терминал не становится четырёхмерным. Изменение XW меняет пространственные
координаты; тесты проверяют смешивание, ортогональность матрицы и изменение кадра.
Near-plane проверки защищают оба перспективных деления.

## Проверки и демонстрация

```powershell
python tools/smoke.py
python -m unittest discover -s tests -v
python -m ascii_tree view --seed 42 --mode 4d --frames 2
```

Первая команда — конечный headless smoke test. Вторая проверяет генерацию,
связность, детерминизм, геометрию 3D/4D, occlusion, размеры, CLI, экспорт и
контроллер терминала. Третья проверяет реальный старт/выход внутри TTY.

- [Сценарий интерактивной проверки на 2 минуты](DEMO.md).
- [Результаты и ограничения проведённых проверок](VERIFICATION.md).
- [Решения, ограничения рендерера и производительность](IMPLEMENTATION_NOTES.md).
- [Сохранённые кадры](samples/): seed 42 во всех режимах, XW 0°/45°, seed 137.
  `manifest.json` содержит параметры и SHA-256; `contact-sheet.png` — превью
  этих текстовых кадров, не входной ресурс приложения.

Пересоздать ASCII-артефакты: `python tools/build_samples.py`. Необязательный
`python tools/make_preview.py` создаёт PNG, если Pillow уже установлен; он не
нужен ни приложению, ни тестам. GUI Windows Terminal и реальная Linux/WSL-сессия
требуют отдельных ручных проверок; PTY и симуляции отмечены в отчёте явно.
