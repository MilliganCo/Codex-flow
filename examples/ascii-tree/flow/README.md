# ASCII Tree Explorer

Процедурное лиственное дерево в терминале: **2D, 3D и проекция 4D-данных**.
Ствол, ветви трех порядков, сужающаяся толщина и разреженная крона строятся по seed.
Один объект сохраняется при переключении режимов; только `G` создает следующее дерево.

## Запуск за минуту

Нужен **Python 3.12+**. Внешних зависимостей, установки пакетов и сети нет.
В PowerShell 7 откройте каталог проекта в Windows Terminal:

```powershell
python --version
python -m ascii_tree --help
python -m ascii_tree view --seed 42 --mode 3d
```

Эквивалентный короткий entrypoint для PowerShell:

```powershell
.\ascii-tree.ps1 view --seed 42 --mode 3d
```

Рекомендуемое окно — 100×40 или больше, моноширинный шрифт, английская раскладка
для буквенных команд. Дерево и интерфейс используют печатаемый ASCII; меню на
английском, чтобы не зависеть от кодовой страницы. `H` открывает справку.
В Linux/WSL используются те же команды с `python3` вместо `python`, при Python 3.12+.
Linux/WSL здесь не запускались; основная проверенная платформа — Windows ConPTY.

## Управление

- `1` / `2` / `3`: 2D / 3D / 4D; текущий режим виден в первой строке.
- Стрелки: поворот и наклон камеры в 3D/4D. `[` / `]`: XW-поворот в 4D.
- `+` / `-`: масштаб; `=` также увеличивает. `Space`: анимация / пауза.
- `G`: следующий seed; `R`: исходные углы и масштаб, время 0, пауза.
- `E`: экспорт; `H` / `?`: справка; `Q` / `Esc` / `Ctrl+C`: выход.

Анимация вращает камеру в 3D и камеру вместе с XW-плоскостью в 4D.
В 2D изображение остается неподвижным. Ориентация между режимами сохраняется.
Во время справки анимация приостановлена. `R` не меняет seed и объект дерева.

`E` записывает только растровую область дерева в `exports/tree-SEED-MODE-NNN.txt`.
Меню, подсказки и ANSI в этот файл не попадают. Номер выбирается без перезаписи
предыдущих экспортов. Для другого каталога: `view --export-dir my-frames`.
При окне 100×40 дерево занимает 99×35: оставлены строки для меню и запас против
автопереноса последнего столбца. Resize пересчитывает область; минимальная — 1×1.
На очень узком окне управление работает, но справка и само дерево обрезаются.

## Headless CLI и точный экспорт

```powershell
python -m ascii_tree render --seed 42 --mode 2d --width 100 --height 40 --output tree-2d.txt
python -m ascii_tree render --seed 42 --mode 3d --yaw 70 --pitch -12 --output tree-3d.txt
python -m ascii_tree render --seed 42 --mode 4d --angle4d 65 --width 100 --height 40 --output tree-4d.txt
```

Без `--output` кадр идет в stdout. Для сохранения используйте `--output`: это
исключает перекодировку через PowerShell. Файл содержит ровно `height` строк по
`width` печатаемых ASCII-символов, включая завершающие пробелы; каждая строка
заканчивается одним байтом LF. Нет BOM, CR, цвета и управляющих последовательностей.
Заданный родительский каталог выходного файла должен уже существовать.

Все параметры можно увидеть через `python -m ascii_tree render --help`:

- `--seed` — целое число; `--mode` — `2d`, `3d` или `4d`.
- `--width`, `--height` — положительные размеры, максимум 1 000 000 ячеек.
- `--yaw`, `--pitch`, `--angle4d` — углы в градусах, по умолчанию 25, -8, 0.
- `--zoom` — 0.15–5; `--aspect` — высота/ширина ячейки, 0.5–4, по умолчанию 2.
- `--time` — воспроизводимое время анимации: +12°/с yaw и +8°/с XW.

Например, фиксированный момент анимации:

```powershell
python -m ascii_tree render --seed 42 --mode 4d --time 2.5 --angle4d 30 --output at-2.5s.txt
```

Одинаковые входные параметры дают одинаковые байты в проверенном окружении.
Headless `render` не требует TTY. `view` при перенаправленном stdin или stdout
сразу возвращает код 2 и показывает команду `render`, не печатая бесконечные кадры.

## Что означают 2D, 3D и 4D

Модель — неизменяемый граф `Tree`: вершины `(x,y,z,w)`, сегменты с начальным и
конечным радиусами и индексом сегмента-предка. `w` равен накопленному расстоянию
вдоль пути от корня, умноженному на 0.55: это условные часы развития ветви,
а не высота и не реальный возраст в годах. Z и W действительно изменяются.

**2D** — ортографическая XY-проекция этого графа. **3D** — поворот настоящих XYZ
вокруг двух осей и перспективная проекция с z-buffer. Ближняя ветвь закрывает
дальнюю; оттенки ASCII зависят от глубины и освещения толстой древесины.

**4D** сначала центрирует и равномерно нормирует четыре координаты, затем
выполняет настоящий поворот XW:

```text
x' = x*cos(a) - w*sin(a)
w' = x*sin(a) + w*cos(a)
y' = y; z' = z

4D -> 3D: (X,Y,Z) = (x',y',z') * 4/(4-w')
3D -> 2D: yaw/pitch; d = 4.5 + Zcamera
          screen = (Xcamera,Ycamera) * 4.5/d
```

В 2D последний перспективный множитель отсутствует. Для растра учитывается
соотношение сторон ячейки. Деления у ближней плоскости отсеиваются. При `a=0`
4D может уже отличаться от 3D из-за перспективы по W. При изменении `a` разные
стадии ветвей смещаются по-разному: это не замена дерева и не горизонтальный сдвиг
готовой картинки. Большой XW-поворот закономерно делает силуэт менее привычным.

## Проверка одной командой

```powershell
python scripts/smoke.py
```

Полный конечный набор автоматических тестов без установки pytest:

```powershell
python -m unittest discover -s tests -v
```

В Windows набор включает настоящий ConPTY: управление, экспорт, анимацию, размеры
100×40 → 30×12 → 1×1 → 100×40 и Q/Esc/Ctrl+C. На других ОС этот конкретный тест
помечается `skipped`; остальные не требуют терминала. Тесты создают временные файлы
внутри проекта и удаляют их. Отдельная консольная демонстрация с сохранением артефактов:

```powershell
python scripts/terminal_smoke.py
python scripts/benchmark.py
```

Повторный консольный smoke сохраняет новый каталог `artifacts/terminal-N`, не стирая
предыдущий. Сведения о покрытии и ограничениях — в [VERIFICATION.md](VERIFICATION.md),
решения и компромиссы — в [IMPLEMENTATION_NOTES.md](IMPLEMENTATION_NOTES.md).
