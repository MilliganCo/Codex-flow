# Implementation notes

## Выбор стека и границы

Python 3.12, только стандартная библиотека. Это позволяет запускать проект
офлайн без pip, сборки пакетов, wheels, curses и зависимостей Textual.
Основной entrypoint — `python -m ascii_tree`; PowerShell launcher необязателен.
Генерация, математика, растеризация, состояние и терминальный ввод разделены.

Все рабочие действия выполнялись в выданном workspace одним агентом.
Другие ветки, независимый оценщик, сеть, дополнительные модели и глобальные
настройки не использовались. Установленный вне workspace навык codex-flow
не читался из-за запрета выхода за его границы.

## Геометрия

`model.py`: неизменяемый Tree содержит вершины Vec4, сегменты и листья.
Сегмент ссылается на старт/конец, родителя, порядок ветвления и два положительных
радиуса. Конец родителя совпадает со стартом потомка. Все новые вершины
присоединяются к уже достижимой вершине. Повторный seed использует собственный
`random.Random`, без зависимости от глобального состояния или порядка вызовов.

Ствол из 13 сужающихся участков имеет случайный наклон и изгиб. Боковые ветви
размещаются с близким к золотому углом азимутом; рекурсивные ответвления используют
локальный базис касательной, случайную длину/наклон и слабый гравитропизм.
Порядок ограничен четырьмя, число сегментов — 5000. Для seed 42 получаются
838 сегментов и 5582 отдельных листа. Случайные кластеры находятся у внешних
веточек, сохраняя читаемость крупных ветвей и асимметрию кроны.

W обозначает относительное время рождения по накопленной длине пути от корня.
Лист наследует W своей веточки. Время анимации не пересоздаёт геометрию:
непрерывное поле слабого ветра изменяет только координаты проекции, сохраняя
общие концы сегментов. 3D/4D дополнительно вращают камеру, 4D — гиперплоскость.

## Рендер

`renderer.py`: общая цепочка преобразований и программный depth buffer на
ячейку. 2D — ортографический XY-вид; Z всё ещё определяет перекрытия.
3D — поворот yaw/pitch и перспектива. 4D — центрирование, матричный XW/YW/ZW
поворот, перспектива 4D→3D, камера и перспектива 3D→2D.

Меньшая глубина побеждает независимо от порядка поступления примитивов.
В перспективе глубина вдоль экранного сегмента интерполируется через 1/z;
радиус интерполируется по соответствующему пространственному параметру.
Толщина приблизительно учитывает переднюю поверхность цилиндра. Вдоль линии
наносится эллиптический footprint с учётом aspect; штрихи `/`, `\\`, `|`, `-`
следуют направлению ветви, `|#%` передают освещение и толщину коры.
Листва использует `.' :*o` с изменением тона по глубине.

Liang–Barsky ограничивает растеризацию видимой частью линий. Оба перспективных
деления защищены near-plane 0.5; отвергнутый конец ведёт к пропуску примитива.
При штатных размерах дерева и камере такие отсечения не возникают.
Предел кадра — 240000 ячеек и 1000 по каждой стороне; zoom 0.15–5.

Оптимизация сохраняет точную математику: sin/cos камеры вычисляются один раз
на кадр, а 4D использует четыре ненулевых коэффициента выбранной плоскости
вместо общего умножения 4×4 для каждого листа. Тест сравнивает результат
с полной матрицей и двумя независимыми функциями перспективы.

## Терминал и ошибки

`terminal.py`: alternate screen, скрытый курсор, позиционирование в начало
кадра и перерисовка без прокрутки. Последняя колонка резервируется от autowrap.
Статичная сцена обновляется только по событию; resize опрашивается без потоков.
Анимация ограничена fps, значение по умолчанию 8. Экспорт пишет ASCII/LF через
байтовый интерфейс, с исключительным созданием файла и уникальным суффиксом.

Windows: msvcrt и временные настройки VT output / raw key input через ctypes.
Отключение processed/line/echo input позволяет получить Ctrl+C как клавишу
даже в проверенном ConPTY-хосте. Оба исходных console mode восстанавливаются
в контекстном менеджере, в том числе при исключениях. POSIX: termios, cbreak,
select и декодирование ANSI-стрелок с короткой задержкой одиночного Escape.
Нет TTY — `view` возвращает один чистый кадр вместо запуска цикла.

Код возврата CLI: 0 при успехе, 2 при неверных параметрах/ошибке ввода-вывода,
130 при Ctrl+C. Закрытый downstream pipe обрабатывается без traceback.
Ошибки экспорта интерактивно показываются в строке состояния.

## Performance notes

Замер `python tools/benchmark.py --frames 7 --output examples/benchmark.json`
на Python 3.12.10 / Windows, seed 42, 100×40: генерация 33.30 мс;
медианы 2D / 3D / 4D — 25.58 / 27.43 / 30.44 мс на кадр.
Это время генерации ASCII, без стоимости вывода в терминал; аппаратную
скорость и одинаковую частоту на других компьютерах эти цифры не гарантируют.
Замер конечный: один прогрев и семь кадров на режим. Все значения сохранены
в JSON. Программа рассчитана на обычные терминальные размеры, не на 1000×1000.

## Trade-offs и известные ограничения

- Это стилизованное широколиственное дерево, не ботанический симулятор.
  Мелкие ветви имеют минимальный размер штриха, поэтому тоньше ячейки не бывают.
- Лист — одна непрозрачная ячейка; нет прозрачности, полутонов и subcell AA.
  Перекрытия и цилиндрическое освещение являются приближением на уровне ячеек.
- В сильном наклоне, увеличении и 4D-повороте дерево может выходить за кадр.
  Фиксированная базовая рамка помогает видеть изменение формы без автозума.
- При узком/низком окне справка сокращается. Для всех клавиш нужен README
  или окно около 80×30 и больше. В 1×1 осмысленная визуализация невозможна.
- Адаптер инструментального Windows PTY отбрасывал `[` и `]` даже в отдельном
  тесте msvcrt; альтернативы `,` / `.` проверены реально. Linux/WSL и ручное
  изменение размера настоящего окна в этой среде не проверены.

Детерминизм подтверждён на одной версии интерпретатора. Побайтовая идентичность
между разными реализациями floating point / версиями Python не обещается.
Полный перечень выполненных и невыполненных проверок — в TEST_REPORT.md.
