# ASCII Tree Explorer

Живое процедурное дерево в терминале: общий граф ветвей, ортографический 2D,
объёмный 3D и настоящая проекция четырёхмерных данных. Ствол сужается, ветви
изгибаются и разветвляются до четвёртого порядка, листва оставляет просветы.
Никаких изображений, GPU, сети или API. Растер использует только печатаемый ASCII.

## Запуск за одну команду

Из каталога проекта, с Python **3.12 или новее**:

```powershell
python -m ascii_tree view --seed 42 --mode 3d
```

Рекомендуемая среда: Windows 11, Windows Terminal, PowerShell 7, моноширинный
шрифт, окно около 100×40. Устанавливать пакеты не нужно: приложение, тесты и
утилиты используют только стандартную библиотеку. `requirements.txt` фиксирует
отсутствие сторонних зависимостей. Проверенная версия Python — 3.12.10.

Если команда `python` не найдена, используйте `py -3.12` вместо `python`.
В Linux/WSL команда обычно начинается с `python3`; POSIX-адаптер включён,
но в данной среде его работа не проверялась.

Дополнительные варианты запуска:

```powershell
python -m ascii_tree
python -m ascii_tree --help
python -m ascii_tree view --help
python -m ascii_tree render --help
```

Без аргументов открывается `view`. Необязательный Windows launcher:
` .\ascii-tree.ps1 view --seed 7`; модульная команда выше не зависит от политики
исполнения PowerShell-скриптов. Файл `ascii_tree_launcher.py` также можно
запускать по абсолютному пути из другого каталога.

## Управление

Режимы и ориентация:

- `1` / `2` / `3` — 2D / 3D / 4D. Объект и seed сохраняются.
- Стрелки влево/вправо — поворот камеры; вверх/вниз — наклон в 3D и 4D.
- `[` / `]` — уменьшить/увеличить угол 4D на 7° в выбранной гиперплоскости.
- `,` / `.` — альтернативы `[` / `]`; работают и в проверенном PTY-адаптере.
- `+` / `-` — масштаб; `=` также увеличивает. В 2D камера фиксирована в XY.

Сеанс:

- `Space` — запуск/пауза: лёгкий ветер, вращение 3D-камеры, поворот с W в 4D.
- `G` — следующий seed, то есть новое дерево. Начав с 42, получите 43.
- `R` — сброс камеры, масштаба, времени и угла 4D; текущий режим сохраняется.
- `E` — экспорт области дерева в `exports/tree_seed42_3d_001.txt` без интерфейса.
- `H` / `?` — справка; `Q` / `Esc` — выход. `Ctrl+C` также восстанавливает терминал.

Латинские буквы работают в обоих регистрах. Верхняя строка показывает режим
и seed; следующая — углы, масштаб и состояние анимации. Полная справка объясняет
смысл W. Для другой гиперплоскости запустите `view --mode 4d --plane yw` или `zw`.
Анимация изначально приостановлена, предел частоты задаётся `--fps 8` (1–30).

При resize приложение пересчитывает область рисования. Оно оставляет последнюю
колонку свободной, чтобы избежать автопереноса; интерфейс занимает шесть строк.
В узком окне используется сокращённая компоновка, клавиши остаются активны.
Размеры `--width` / `--height` у `view` задают только fallback без TTY.

## Headless CLI и экспорт

Эти команды работают в CI, pipe и перенаправлении без интерактивного терминала:

```powershell
python -m ascii_tree render --seed 42 --mode 2d --width 100 --height 40 --output my-2d.txt
python -m ascii_tree render --seed 42 --mode 3d --yaw 35 --pitch 12 --output my-3d.txt
python -m ascii_tree render --seed 42 --mode 4d --angle4 0 --output before.txt
python -m ascii_tree render --seed 42 --mode 4d --angle4 40 --output after.txt
python -m ascii_tree render --seed 7 --mode 3d --time 2.5 --output seed7.txt
```

`--output -` или отсутствие `--output` выводит только кадр в stdout. Чтобы
получить гарантированные LF-байты в Windows, используйте `--output`, поскольку
старые версии PowerShell могут менять кодировку при перенаправлении stdout.
При отсутствии TTY команда `view` тоже выводит ровно один кадр и завершает
работу; объяснение fallback идёт в stderr. Escape-последовательностей в нём нет.

Все входы рендера доступны в CLI: `--seed`, `--mode`, `--width`, `--height`,
`--yaw`, `--pitch`, `--angle4` (алиас `--angle-4d`), `--plane`, `--zoom`,
`--aspect`, `--time`. Углы задаются в градусах, время — в секундах. При `time=0`
ветер отсутствует. По умолчанию: seed 42, 100×40, yaw −20°, pitch 8°, XW 0°,
zoom 1, aspect 0.5. Aspect — ширина ячейки, делённая на её высоту.

Файл содержит ровно `height` строк по `width` печатаемых ASCII-символов;
пробелы справа сохраняются. Разделитель — LF, после последней строки есть LF,
без BOM, CR, ANSI и заголовков. Для 100×40 это 4040 байт. Воспроизводимость
проверяется побайтово на одной версии Python; между разными платформами/версиями
Python возможны различия округления на границах ячеек.

Каждая сторона допускает 1–1000 символов, общий предел — 240000 ячеек.
Параметры проверяются до генерации. Экспорт по `E` использует текущий размер
области дерева, состояние камеры и время; справка и панели в него не входят.
Существующие файлы `E` не перезаписывает. Каталог меняется через `--export-dir`.

## Что здесь означает 4D

Каждая вершина хранит `(x, y, z, w)`. Три пространственные координаты формируют
то же дерево во всех режимах. W — нормированное время рождения ветви,
пропорциональное длине пути от корня: `w = 12 * (path_length / max_path - 0.5)`.
Это координата, а не переключатель другого случайного дерева.

Перед проекцией пространственный центр дерева переносится в начало координат.
Для XW-поворота применяется настоящая ортогональная матрица:

```text
x' = cos(a) * x - sin(a) * w
y' = y
z' = z
w' = sin(a) * x + cos(a) * w

k4 = d / (d - w')
(X, Y, Z) = k4 * (x', y', z')       # 4D -> 3D

(xc, yc, zc) = camera_yaw_pitch(X, Y, Z)
k3 = d / (d + zc)
(u, v) = (xc * k3, yc * k3)         # 3D -> 2D
```

YW/ZW работают аналогично, смешивая W с соответствующей осью. Расстояние `d`
подбирается по размеру дерева, не менее 32. Оба перспективных деления имеют
ближнюю плоскость. Затем учитываются масштаб и соотношение сторон ячейки.
Терминал показывает **проекцию 4D-данных**, а не сам четырёхмерный объём.
2D использует ортографическую XY-проекцию; 3D — перспективную камеру без W.

## Проверки

Полный набор и короткий smoke test — две отдельные команды:

```powershell
python -m unittest discover -s tests -v
python tools/smoke.py
```

Тесты проверяют граф, tapering, конечность и вариативность координат, ASCII/LF,
размеры, перспективу, взаимное перекрытие сегментов, все три гиперплоскости,
сохранение объекта при смене режимов, клавиши, паузу, resize, безопасный 1×1,
ошибки экспорта, CLI как дочерний процесс и восстановление терминала.
Отдельно проверяется совпадение оптимизированного 4D-рендера с полной матрицей.
Временные файлы проверок находятся в `.tmp/` внутри проекта.

Производительность: `python tools/benchmark.py --frames 7`.
Измеренный результат сохранён в [examples/benchmark.json](PACKAGING.md#omitted-generated-artifacts).
Проверки и ограничения перечислены в [TEST_REPORT.md](PACKAGING.md#omitted-generated-artifacts).

## Сценарий проверки интерактивности — около 90 секунд

1. Откройте `python -m ascii_tree view --seed 42 --mode 2d` в окне 100×40.
   Нажмите `2`, несколько стрелок, затем `3`. Seed должен остаться 42.
2. Нажмите `]` пять раз (или `.` пять раз), затем `[` пять раз. Крона и ветви
   должны менять форму проекции; строка XW меняется шагами по 7°.
3. Нажмите `Space`, подождите 3 секунды, снова `Space`; нажмите `+`, `-`, `R`.
   Убедитесь, что анимация остановилась, а сброс вернул масштаб 1 и XW 0°.
4. Откройте `H`, закройте `?`, нажмите `E`. Уменьшите окно до 25×10 и снова
   увеличьте. Нажмите `G`: появится seed 43. Экспорт должен содержать только дерево.
5. Выйдите через `Q`. Повторите запуск и выход через `Esc`, затем через `Ctrl+C`.
   Курсор и обычный экран должны восстановиться. Сравните seed 7 и 42.

Известные компромиссы: лист — одна непрозрачная ячейка; микроветки показываются
минимальным штрихом; при большом масштабе и сильных 4D-поворотах возможен crop.
В очень маленьком окне дерево неразличимо, но управление и выход работают.
Подробности реализации — в [IMPLEMENTATION_NOTES.md](IMPLEMENTATION_NOTES.md).
