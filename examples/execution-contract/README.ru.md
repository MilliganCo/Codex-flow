# Главный Sol и ограниченное предложение Luna

[English](README.md)

Контракт владельца поручает Luna medium предложение отдельного модуля. Sol XHigh
пишет CLI, проверяет и один раз интегрирует исходник; он остаётся единственным
писателем файлов. Внешний проверяющий в официальном sandbox запускает CLI и
сравнивает AST сохранённого предложения с интегрированным модулем.

Посмотреть маршрут без модели, создания рабочих каталогов и исполнения:

```powershell
python codex-flow.py --repo examples/execution-contract run --task-file examples/execution-contract/task.md --execution-contract examples/execution-contract/execution.json --acceptance-file examples/execution-contract/acceptance.json --dry-run
```

Перед живым запуском скопируйте четыре входных файла в новый проект:
`task.md`, `execution.json`, `acceptance.json`, `verifier.py`. Проверьте их.
Используйте те же аргументы `run` с абсолютными путями, установленным официальным
`--codex` и `--enable`, убрав `--dry-run`. Запуск расходует текущую подписку
ChatGPT; платного API-фолбэка нет. Задайте конечные лимиты проекта и сохраняйте
все попытки. До генерации здесь намеренно нет app.py и core.py.

Для приёмки нужны наблюдаемый вызов нужного помощника, все артефакты и успешные
внешние проверки. Области — логическая ответственность: помощники наследуют
разрешения родителя. Один файл предложения ещё не доказывает его происхождение
от помощника. Этот пример не устанавливает универсального ускорения.
